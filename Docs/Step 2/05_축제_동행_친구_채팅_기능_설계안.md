# 축제 동행 찾기 · 친구 · 채팅 기능 설계안

> 상태: 신규 기능 제안. 기존 기획서·API·DB 설계에 아직 반영되지 않았으며, 구현 범위와 일정은 팀에서 확정한다.

## 1. 기능 개요

사용자는 축제별 동행 모집 글을 작성하거나 참여 신청할 수 있다. 작성자가 신청을 승인하면 동행방에 입장해 단체 채팅을 하고, 확정된 만남 장소를 지도에서 확인한다. 동행에서 알게 된 사용자와 친구 관계를 맺으면 1:1 또는 단체 채팅을 계속할 수 있다.

```text
축제 선택 → 모집 글 작성·조회 → 참여 신청 → 작성자 승인
→ 동행방 채팅·만남 장소 확정 → 동행 종료
                                 ↘ 친구 신청·수락 → 친구 1:1·단체 채팅
```

## 2. 신규 기능 탭

```text
동행 찾기 | 채팅 | 친구 | 마이페이지
```

| 탭 | 주요 기능 |
|---|---|
| 동행 찾기 | 축제별 모집 글 조회·작성, 참여 신청 |
| 채팅 | 진행 중인 동행방, 친구 1:1·단체방, 지난 동행 |
| 친구 | 친구 검색·신청·수락·목록, 친구 단체방 만들기 |
| 마이페이지 | 내 모집 글·신청 내역, 프로필·설정 |

이 표는 새로 추가할 기능의 탭만 다룬다. 기존 축제 탐색 화면의 구성은 이 설계 범위에서 정하지 않는다. 탭은 동행이나 친구가 없어도 유지하며, 목록이 비어 있으면 해당 기능으로 이동하는 안내를 표시한다.

## 3. 동행 모집 글

### 작성 화면

축제 상세에서 `동행 모집하기`를 누르면 현재 축제를 자동 연결한다.

| 항목 | 입력 방식 | 예시·규칙 |
|---|---|---|
| 축제 | 자동 선택 | 현재 보고 있는 축제의 `festival_id` 저장 |
| 만날 날짜 | 날짜 선택 | 축제 기간 안의 미래 날짜 |
| 만날 시간 | 시간 선택 | 미래 시각 |
| 희망 연령대 | 선택 | 20대·30대·무관 등 |
| 희망 성별 | 선택 | 남성·여성·무관 |
| 모집 인원 | 숫자 선택 | 작성자를 제외한 추가 모집 인원 |
| 간단 메모 | 짧은 글 | 관람 계획·대략적인 집결 구역 |

글을 게시하면 작성자만 들어가 있는 **동행방**이 함께 생성된다. 만남 장소는 처음에 `미정`이다.

### 목록과 신청

모집 글 카드에는 축제명, 만남 날짜·시간, 연령대·성별 조건, 모집 현황, 메모, 모집 상태를 표시한다. 신청자는 `동행 참여하기`를 눌러 짧은 신청 메시지를 보낸다. 작성자는 신청 관리 화면에서 승인하거나 거절한다.

- 승인 전 신청 상태는 `승인 대기`이며 신청자는 취소할 수 있다.
- 승인된 인원만 정원에 반영한다. 동시 승인으로 정원을 넘지 않도록 서버 트랜잭션에서 검사한다.
- 승인된 신청자에게 알림을 보내고, 채팅 탭의 동행방 목록에 방을 표시한다.
- 정원이 차면 모집을 마감하고 새 신청을 받지 않는다.
- 작성자는 본인 글에 신청할 수 없으며 같은 글에 중복 신청할 수 없다.

## 4. 동행방

동행방은 작성자와 **승인된 참여자 전원**의 단체방이다. 승인 전 신청자는 채팅과 정확한 만남 장소를 볼 수 없다.

```text
서울빛초롱축제 동행방
──────────────────────────
12월 7일 오후 6시 · 참여자 3명

📍 만남 장소
광화문역 5번 출구
“출구 앞 안내판 옆에서 만나요”
[지도 보기] [주소 복사]
작성자에게만: [장소 수정]

[참여자 목록]  프로필 보기 · 친구 신청

[단체 채팅]
작성자: 5시 50분쯤 도착할게요.
참여자: 저도 그때 도착합니다.
```

### 만남 장소 확정

1. 작성자가 장소를 검색하거나 지도에서 위치를 선택한다.
2. 장소명·주소·좌표를 확인하고 상세 안내를 입력한다.
3. `만남 장소 확정`을 누르면 방 상단에 장소 카드와 지도 핀이 표시된다.
4. 장소 변경 시 카드의 최신 정보와 수정 시각을 갱신하고, 채팅에 시스템 메시지를 남기며 참여자에게 알린다.

채팅에서 장소를 논의할 수 있지만 **최종 약속 정보는 상단 장소 카드**를 기준으로 한다. 지도 로딩에 실패해도 장소명·주소·상세 안내는 표시한다.

동행방에는 임의 친구 초대를 제공하지 않는다. 참여자는 모집 글 신청과 작성자 승인을 통해서만 입장하며, 모집 정원과 방 멤버가 일치해야 한다.

## 5. 친구 탭

```text
친구
[친구 목록] [받은 신청] [보낸 신청]

[닉네임 또는 사용자 코드로 찾기]
[친구 단체 채팅방 만들기]

민지  [1:1 채팅]
지훈  [1:1 채팅]
```

동행방 참여자의 프로필이나 검색 결과에서 친구를 신청한다. 상대가 수락하면 친구 목록에 추가된다. **동행 참여·승인은 자동 친구 추가가 아니다.** 친구 신청 취소·거절·친구 삭제·차단 기능을 제공한다. 사용자 검색에 실명·전화번호·이메일을 기본 검색 조건으로 사용하지 않는다.

## 6. 채팅 종류와 화면

```text
채팅
[전체] [동행방] [친구 채팅] [지난 동행]

동행방       서울빛초롱축제 · 참여자 3명 · 장소 확정
친구 채팅    민지 · 1:1
친구 채팅    주말 축제 모임 · 단체 4명
지난 동행    부산불꽃축제 · 종료
```

| 방 종류 | 생성·입장 조건 | 유지·종료 |
|---|---|---|
| 동행방 | 모집 글 게시 시 생성. 작성자와 승인된 참여자만 입장 | 동행 종료 후 지난 동행으로 이동, 읽기 전용 |
| 친구 1:1 | 서로 친구인 두 사람이 시작 | 동행 종료와 무관하게 유지 |
| 친구 단체방 | 방을 만드는 사용자가 친구 2명 이상을 선택 | 동행 종료와 무관하게 유지 |

채팅의 메시지 저장·전송·읽음 처리 기능은 공통으로 구현하고, 방 종류에 따라 생성·입장·초대 권한을 다르게 적용한다.

### 친구 단체방 만들기

친구 탭의 `친구 단체 채팅방 만들기` 또는 채팅 탭의 `새 채팅`에서 친구 2명 이상을 선택하고 방 이름을 정한다. 초대받은 사용자는 초대를 수락한 뒤 입장한다. 수락 전 메시지는 볼 수 없고, 첫 버전에서는 입장 이후 메시지만 표시한다.

- 방을 만든 사람이 방장이며 방 이름 변경과 추가 초대를 관리한다.
- 멤버는 스스로 나갈 수 있다. 방장이 나갈 때는 다른 멤버에게 방장 권한을 넘긴다.
- 친구 삭제 후 기존 1:1 대화의 보존·전송 정책과 단체방 내 차단 사용자 처리 방식은 구현 전에 확정한다.
- 동행방 멤버끼리 계속 대화하려면 친구 신청·수락 후 별도 친구 단체방을 만든다.

## 7. 동행 종료

작성자가 직접 종료하거나, 만남 시각 이후 팀이 정한 시간이 지나면 자동 종료한다. 자동 종료는 실제 만남을 확인했다는 뜻이 아니다. 약속 전에 취소하면 `종료`와 구분해 `취소`로 표시하고 참여자에게 알린다.

| 대상 | 종료 후 처리 |
|---|---|
| 동행 모집 글 | `종료` 표시, 새 신청·승인 불가 |
| 동행방 | `채팅 → 지난 동행`으로 이동 |
| 동행방 메시지 | 읽기 전용 |
| 만남 장소·지도 | 지난 동행에서 확인 가능하도록 보존 기간 설정 |
| 친구 관계 | 유지 |
| 친구 1:1·단체 채팅 | 유지 |
| 채팅·친구 탭 | 계속 표시 |

## 8. 데이터 구조 초안

기존 `festivals`와 `profiles`에 연결한다.

| 테이블 | 주요 데이터 |
|---|---|
| `companion_posts` | 축제, 작성자, 만남 시각, 연령·성별 조건, 모집 인원, 메모, 상태 |
| `companion_applications` | 모집 글, 신청자, 신청 메시지, 승인·거절 상태 |
| `meeting_places` | 동행방, 장소명, 주소, 위도·경도, 상세 안내, 수정 시각 |
| `friend_requests` | 요청자, 수신자, 대기·수락·거절 상태 |
| `friendships` | 친구인 두 사용자 |
| `user_blocks` | 차단 사용자와 대상 사용자 |
| `chat_rooms` | 방 종류(`companion`·`direct`·`friend_group`), 이름, 연결된 모집 글, 상태 |
| `chat_members` | 방별 사용자, 역할, 초대·입장·퇴장 상태와 시각 |
| `chat_messages` | 방, 발신자, 일반·시스템 메시지, 내용, 전송 시각 |
| `notifications` | 신청·승인, 친구 신청·수락, 방 초대, 장소 변경 알림 |

`companion_applications`에는 `(post_id, applicant_id)` 고유 제약을 둔다. 채팅방 멤버 조회와 메시지 읽기·전송 권한은 서버와 실시간 구독 단계 모두에서 검사한다.

## 9. 권한과 운영 규칙

- 로그인한 사용자만 모집 글 작성·참여 신청·친구 신청·채팅을 할 수 있다.
- 작성자만 참여 승인·거절, 동행 만남 장소 확정·수정을 할 수 있다.
- 승인된 동행방 멤버만 해당 채팅과 정확한 장소를 조회할 수 있다.
- 친구 1:1 채팅은 친구 관계와 차단 상태를 확인한다.
- 친구 단체방은 초대 수락 및 현재 멤버 상태를 확인한다.
- 개인 연락처와 실시간 위치는 이 기능의 필수 정보로 수집하지 않는다.
- 신고·차단·부적절한 메시지 처리와 탈퇴·데이터 보존 정책을 마련한다.

## 10. 권장 구현 순서

1. 모집 글 작성·조회, 참여 신청·승인·정원 관리
2. 공통 채팅방·멤버·메시지 기능
3. 동행방과 만남 장소 검색·지도 표시·변경 알림
4. 친구 신청·수락·목록·차단
5. 친구 1:1 채팅
6. 친구 단체방 생성·초대·방장·나가기
7. 동행 종료·지난 동행, 신고·운영 기능

기존 프로젝트의 대표 시연 범위는 축제 탐색과 AI 귀가 경로 조회다. 이 기능을 채택할 때는 별도 요구사항, API, DB 마이그레이션, 담당자와 일정을 함께 반영한다.
