## 목적과 범위

공식 축제 안내문을 대상으로 `text-embedding-3-small`의 `dimensions=1024` 설정을 시험한다. 아래는 **시험 후보와 기대 결과**이며, 문서 수집·승인·임베딩·실제 검색을 완료했다는 뜻은 아니다. 실시간 혼잡, 날씨, 현재 취소 여부는 이 정적 문서 검색으로 판정하지 않는다.

최신 기획서의 A42 `지금 핫한 축제`는 외부 사이트의 축제 순위·언급 정보를 사전 수집하는 추천 기능이다. 그 수집 결과는 공식 운영 공지·FAQ가 아니므로 이 RAG 시험 문서에 섞지 않는다. 웹 크롤링 허용 범위도 A42로 한정된다.

## 11/24 실행·기록 항목

1. D1·D2의 원문·축제 ID·승인·효력기간을 확인한다. D3을 대체할 실제 만료 축제의 공식 문서를 확보한 뒤 운영 DB 적재 여부를 정한다.
2. 문서와 질문 모두 같은 `text-embedding-3-small`·`dimensions=1024` 설정을 사용한다. 선택 모델 ID, 요청 차원, 실행일, 청킹 설정, 인덱스, `top_k`, 검색 필터, 문서 버전을 기록한다.
3. 각 질문마다 검색된 문서 ID/축제 ID/점수와 최종 채택 근거, 답변 또는 보류, 소요 시간과 호출 비용을 남긴다. 검색 실패와 답변 생성 실패를 구분한다.
4. Q01~Q10을 실행해 틀린 답이 나오면 원인이 ID/기간 필터, 검색 순위, 근거 채택 중 어디에 있는지 기록한다. **BFCL 통과만으로 운영 모델을 최종 결정하지 않는다.**

모델·차원 확정과 별개로, 다른 축제·만료 문서 차단은 메타데이터 필터가 담당해야 한다. 현재 DB 설계의 `VECTOR(1024)`는 이 1차안과 호환되지만, 임베딩 모델을 변경하면 기존 벡터를 섞지 않고 다시 생성한다.

### 검색 쿼리 계약 초안

```sql
SELECT c.chunk_id, c.document_id, d.festival_id, d.source_url,
       d.effective_from, d.effective_to, c.content,
       c.embedding <=> :query_embedding AS cosine_distance
FROM rag_chunks AS c
JOIN rag_documents AS d ON d.document_id = c.document_id
WHERE d.approval_status = 'approved'
  AND d.festival_id = :selected_festival_id
  AND (d.effective_from IS NULL OR d.effective_from <= :as_of)
  AND (d.effective_to IS NULL OR :as_of < d.effective_to)
  AND c.embedding_model = 'text-embedding-3-small'
  AND c.embedding_version = :embedding_version
ORDER BY c.embedding <=> :query_embedding
LIMIT 5;
```

`effective_to`는 **종료 시각을 포함하지 않는 상한**으로 통일한다. 종료일만 있는 문서는 다음 날 0시 KST로 저장한다. 예를 들어 11/21 종료 행사는 `2026-11-22T00:00:00+09:00`으로 저장한다. 종료일 근거가 없으면 임의로 채우지 않고 승인 과정에서 확인한다. `published_at`이 없으면 원문 게시일을 추정하지 않는다.

### 11/24 실제 임베딩 호출 결과의 범위

`dayoung 1574321`에서 D1 서울빛초롱축제, D2 청계천의 빛, D3 만료 시험 자료와 질문 10개를 `text-embedding-3-small`, `dimensions=1024`로 실제 OpenAI 임베딩 API에 보냈다. 호출·벡터 길이 검증·코사인 순위 계산은 오류 없이 끝났다. Q01~Q04는 기대 문서가 각 선택 축제의 1위였고, Q07은 만료 문서가 검색 자격에서 제외됐다. 표의 점수는 **재실행 결과의 코사인 유사도**이며 합격 임계값이 아니다. 기존 서울윈터페스티벌 시험 자료의 점수는 사용하지 않는다.

이 시험은 짧게 바꿔 쓴 문장 3개를 메모리에서 비교했다. PostgreSQL·HNSW·운영 승인 필터·청크 분할·답변 생성과 보류 판단은 실행하지 않았다. 현재 D1·D2는 공개 축제 ID와 연결됐고 D3만 분리된 만료 자료다. Q05~Q06과 Q08~Q10의 검색 결과가 존재한다는 사실만으로 답변 가능하다고 판정하지 않는다. 출력에 사용량·호출 비용·지연 시간이 없으므로 이 값은 미측정으로 둔다. 첫 결과 JSON은 맥북 임시 폴더의 `backend/agents/rag/sample_eval_results.json`에 저장됐으며, 본 표는 사용자에게 전달된 터미널 출력을 근거로 작성했다.

### 다음 확인: 별도 pgvector 시험 DB

현재 저장소에는 `rag_documents`·`rag_chunks` 스키마와 HNSW 인덱스 정의가 있지만 공식 안내문 승인·적재·검색 API는 아직 구현되지 않았다. 운영 DB에 D1·D2를 승인된 자료로 직접 넣지 않는다. `backend/agents/rag/search.py`에 **실제 테이블 이름을 사용하는 읽기 전용 검색 함수**를 추가했다. 선택 축제 ID·승인·효력기간·임베딩 모델/버전을 SQL에서 제한하고 출처·본문·코사인 거리를 반환한다. 답변 생성과 근거 채택은 이 함수의 범위 밖이다. `backend/agents/rag/check_pgvector_sample.py`는 이름이 `rag_scratch`인 **별도 시험 DB**에만 접속하고 실제 테이블 이름을 가진 임시 테이블을 만든다. D1·D2, 만료된 D3, 미승인 대조 문서 D4를 넣어 같은 검색 함수를 확인한다. 임시 행은 연결 종료 후 사라진다. 이 결과는 운영 DB 적재·승인 또는 실제 서비스 RAG 검증으로 기록하지 않는다.
