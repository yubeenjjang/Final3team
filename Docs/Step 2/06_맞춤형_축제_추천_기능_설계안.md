# 맞춤형 축제 추천 기능 설계안

> 상태: 신규 기능 제안. 기존 필수 기능·API·DB 설계에 아직 반영되지 않았다. 이 문서는 축제 탭의 추천 화면과 취향 설정 흐름을 정의한다.

## 1. 사용자가 경험하는 전체 흐름

```text
회원가입 → 첫 로그인 → 취향 선택 안내
                    ├─ 시작 → 5가지 취향 카드를 좌우로 넘기며 선택 → 내 정보에 저장
                    │        → 맞춤 축제 사진 카드 → 추천 축제 리스트 → 축제 상세
                    └─ 건너뛰기 → 축제 탭의 추천 배너 표시 → 나중에 다시 시작 가능
```

로그인할 때마다 취향 선택을 반복하지 않는다. 저장된 취향이 있으면 바로 축제 탭에 맞춤 추천을 표시한다. `마이페이지 → 나의 축제 취향`에서 언제든 다시 선택할 수 있다.

## 2. 축제 탭 화면 구성

축제 탭은 아래 순서로 네 영역을 보여준다. 이 기능의 `축제 탭`은 기존 축제 목록 화면을 확장하는 화면이다.

| 순서 | 영역 | 표시 방식 |
|---|---|---|
| 1 | **나만을 위한 맞춤형 축제** | 사진 카드 가로 넘기기 → `전체보기` 시 기존 축제 리스트와 같은 형식의 전국 추천 목록 |
| 2 | **현재 인기 있는 축제** | 검증된 서비스 지표에 따른 인기 목록 |
| 3 | **전체 축제 리스트** | 전국 축제를 섞어서 일부 표시 → 우측 상단 작은 `전체보기`에서 지역별 목록·필터 제공 |
| 4 | **최신 등록 축제** | 서비스에 최근 공개된 축제 순서로 표시 |

각 축제 카드는 가능한 범위에서 사진, 축제명, 기간, 지역, 장소, 진행 상태를 표시한다. 카드를 누르면 **기존 축제 상세 화면**으로 이동한다. 사진이 없으면 기본 이미지를 쓰고, 축제 내용과 관계없는 사진을 임의로 대체하지 않는다.

## 3. 첫 로그인: 취향 카드 선택

### 화면 동작

첫 로그인 후 `취향 선택하기`와 `건너뛰기`를 제공한다. 시작하면 **5장의 상황 카드**를 좌우로 넘긴다. 한 화면에는 카드의 대표 이미지와 설명을 보여주고, `선택`, `선택 해제`, `다음`, `이전`, `건너뛰기`를 제공한다. 좌우 스와이프는 **카드 이동**이며, 스와이프 방향만으로 취향을 확정하지 않는다. 버튼을 눌러 선택 상태를 명확히 한다.

취향은 여러 개 선택할 수 있다. 예를 들어 `가족`과 `반려견 동반`을 함께 선택할 수 있다. 마지막 카드에서 `선택 완료`를 누르면 계정의 취향 정보를 저장하고 추천 결과로 이동한다. 아무것도 선택하지 않았다면 건너뛰기와 동일하게 처리한다.

| 카드 | 사용자에게 보이는 문구 | 추천에 사용할 조건의 예 |
|---|---|---|
| 가족 | **가족과 여유롭게 즐기기** | 가족 친화, 한가로운 분위기, 편의시설 정보 |
| 친구 | **친구와 신나게 즐기기** | 액티비티·체험·공연 |
| 연인 | **연인과 달달하게 즐기기** | 포토존·야경·분위기 있는 행사 |
| 반려견·아기 | **반려견 또는 아기와 함께하기** | 카드 안에서 `반려견 동반` / `영유아 동반`을 따로 선택 |
| 혼자 | **혼자 편하게 즐기기** | 혼자 참여 가능한 체험·전시·산책형 행사 |

`반려견 동반`과 `영유아 동반`은 서로 다른 조건이다. 한 카드 안에서 각각 선택하게 하되, 실제 동반 가능 여부는 축제의 공식 안내나 검증된 정보가 있어야만 확정 문구로 표시한다.

### 건너뛰었을 때

건너뛴 사용자도 축제 탭의 나머지 세 영역은 이용할 수 있다. 첫 번째 영역에는 추천 축제 대신 다음 배너를 표시한다.

> 취향을 알려주면 나에게 맞는 축제를 찾아드려요. **[맞춤 축제 시작하기]**

배너를 누르면 같은 5장 카드 흐름으로 다시 들어간다. 건너뛴 사실은 계정에 저장해 다음 로그인마다 전체 화면을 강제로 띄우지 않는다.

## 4. 맞춤 추천 결과

### 사진 카드와 리스트

취향을 저장한 직후 추천 축제를 **사진 카드 형태로 좌우 탐색**할 수 있게 한다. 카드에는 `추천 이유`를 짧게 표시한다. 예: `친구와 함께할 체험 프로그램이 있어요`. 카드를 누르면 축제 상세로 이동한다.

`추천 축제 전체보기`를 누르면 **전국 추천 축제 목록**을 기존 전체 축제 리스트와 동일한 카드·정렬·페이지 형식으로 표시한다. 지역, 날짜, 진행 상태 필터를 함께 제공한다. 취향은 추천 순위에 영향을 주되, 사용자가 선택하지 않은 지역의 축제를 자동으로 제외하지 않는다.

`나의 축제 취향 수정` 버튼을 추천 영역과 마이페이지에 둔다. 취향을 변경하면 추천 순위를 다시 계산한다. **취향 저장**과 **관심 축제 저장**은 별개다. 추천 결과에 나타났다는 이유만으로 축제가 관심 목록에 자동 추가되지는 않는다.

### 추천 기준

첫 버전은 규칙 기반 추천으로 구현한다. 축제별로 검증된 태그를 부여하고 사용자 취향과 일치하는 정도로 점수를 계산한다.

```text
추천 점수 = 취향 태그 일치 점수
          + 행사 날짜 적합도
          + 정보 완성도
          + 사용자 관심 저장 여부에 따른 약한 보정
```

- 게시 승인된 축제만 후보로 사용한다.
- 종료·취소된 축제는 기본 추천에서 제외한다.
- 사진, 지역, 날짜, 상세 정보가 확인된 축제를 우선한다.
- `한가로운`, `포토존이 많은`, `반려견 동반 가능`, `영유아 동반 적합` 같은 표현은 **확인 가능한 태그 근거**가 있을 때만 사용한다. 데이터가 없으면 해당 속성을 단정하지 않는다.
- 같은 축제가 사진 카드와 리스트에 중복되는 것은 가능하지만 한 영역 안에서 같은 축제를 반복하지 않는다.
- 추천 근거가 부족하면 `취향과 정확히 일치하는 축제가 아직 없어요`를 표시하고, 전국의 예정 축제로 이동할 수 있게 한다.

AI 추천을 나중에 추가하더라도 실제 축제의 ID와 게시 상태를 DB에서 검증한 뒤 노출한다. 존재하지 않는 축제나 확인되지 않은 동반 가능 조건을 생성하지 않는다.

## 5. 현재 인기 있는 축제

`인기`의 기준을 화면과 운영 정책에 명확히 정한다. 첫 버전은 **최근 7일간 서비스 내 축제 상세 조회 수와 관심 저장 수**처럼 실제 수집 가능한 지표를 사용한다. 예시 가중치는 상세 조회 1점, 관심 저장 5점이며 팀에서 조정할 수 있다.

- 봇·중복 요청을 최대한 제외하고 집계한다.
- 집계가 충분하지 않으면 `인기` 순위를 임의로 만들지 않고 `많이 살펴보는 축제` 또는 `주목할 축제`처럼 검증 가능한 표현으로 대체한다.
- 취소·종료·비공개 축제는 기본 인기 목록에서 제외한다.
- 점수가 같으면 시작일, 축제 ID 등 고정 기준으로 정렬해 순서가 흔들리지 않게 한다.

## 6. 전체 축제 리스트와 지역별 전체보기

축제 탭에는 게시된 전국 축제 중 일부를 **섞인 순서**로 보여준다. 매 화면 요청마다 완전히 재배열하면 스크롤하거나 뒤로 왔을 때 축제가 바뀌므로, 하루 또는 세션 단위의 고정 시드를 사용한다. 같은 조건의 페이지 이동에서는 순서를 유지한다.

영역 우측 상단의 작은 `전체보기`를 누르면 기존 전체 축제 목록 화면으로 이동한다. 상단에 `전국`, 각 시·도 지역 선택, 날짜·상태 필터를 제공한다. 처음에는 `전국`을 선택한 상태로 보여주고, 사용자가 지역을 누르면 해당 지역의 축제만 표시한다.

## 7. 최신 등록 축제

`최신`은 축제 개최일이 아니라 **서비스에 처음 공개된 시각**을 뜻한다. `festivals.published_at` 내림차순으로 표시하며, 같은 시각이면 축제 ID로 순서를 고정한다. 내용 수정이나 재수집으로 `published_at`을 갱신하지 않는다. 종료·취소·비공개 축제는 기본 목록에서 제외한다. 축제 카드를 누르면 기존 축제 상세 화면으로 이동한다.

## 8. 데이터 구조 초안

기존 `festivals`, `profiles`, `favorites`를 활용하고 다음을 추가한다.

| 데이터 | 주요 필드 | 목적 |
|---|---|---|
| `user_festival_preferences` | `user_id`, `selected_scenarios`, `pet_companion`, `infant_companion`, `onboarding_status`, `updated_at` | 사용자 취향과 건너뛰기 상태 |
| `festival_tags` | `festival_id`, `tag`, `evidence_source`, `verified_at` | 추천에 쓰는 검증된 축제 속성 |
| `festival_engagement_daily` | `festival_id`, `date`, `detail_views`, `favorite_adds` | 인기 목록 집계 |

`selected_scenarios`는 `family`, `friends`, `couple`, `pet_or_baby`, `solo` 중 여러 값을 저장한다. 반려견·영유아 세부 선택은 별도 필드로 구분한다. 사용자 취향은 본인만 조회·수정할 수 있다.

## 9. API 초안

| 메서드 | 경로 | 역할 |
|---|---|---|
| `GET` | `/api/me/festival-preferences` | 내 취향·온보딩 상태 조회 |
| `PUT` | `/api/me/festival-preferences` | 취향 선택·변경·건너뛰기 저장 |
| `GET` | `/api/festivals/recommended` | 로그인 사용자의 전국 맞춤 추천, 필터·페이지 적용 |
| `GET` | `/api/festivals/popular` | 검증된 인기 기준의 축제 목록 |
| `GET` | `/api/festivals/discover` | 고정 시드로 섞은 전체 축제 일부 |
| `GET` | `/api/festivals/recent` | 최근 공개된 축제 목록 (`published_at` 기준) |

지역별 전체보기는 기존 `GET /api/festivals`의 지역·날짜·상태 필터를 재사용한다. 추천 API 응답에는 축제 기본 카드 정보와 짧은 `recommendation_reason`, 적용한 취향 태그를 포함한다.

## 10. 예외 화면과 검증 항목

| 상황 | 화면 처리 |
|---|---|
| 취향 선택을 건너뜀 | 추천 시작 배너 표시, 나머지 축제 영역 정상 제공 |
| 선택한 취향과 일치하는 축제 없음 | 이유를 알리고 전체 축제 목록으로 연결 |
| 축제 사진 없음 | 기본 이미지와 축제 정보 표시 |
| 축제 날짜·장소 미확정 | 확인 필요 표시, 확정된 일정처럼 추천 이유에 쓰지 않음 |
| 인기 지표 부족 | 가짜 순위 대신 기준이 분명한 대체 목록 표시 |
| 추천 API 오류 | 추천 영역에 재시도 제공, 전체 축제 목록은 유지 |

구현 검증은 첫 로그인·건너뛰기·재시작, 복수 취향 저장·수정, 추천 결과의 실제 축제 연결, 전국·지역 필터, 안정적인 무작위 정렬, 최신 등록 기준과 동률 정렬, 사용자 간 취향 정보 분리까지 포함한다.

## 11. 구현 순서

1. 축제 탭 네 영역과 기존 축제 목록·상세 연결
2. 5장 취향 카드 온보딩, 건너뛰기 배너, 내 정보 저장·수정
3. 축제 태그와 근거 관리, 규칙 기반 추천, 추천 사진 카드·전국 리스트
4. 인기 집계, 고정 시드 전체 목록, 최신 등록 목록
5. 부족한 데이터·이미지·API 오류 화면과 권한·품질 검증

축제 이미지의 사용 조건과 태그 근거를 확인한 뒤 서비스에 표시한다. 기존 기획서의 AI 방문 코스 추천과 이 기능의 **축제 발견 추천**은 서로 다른 흐름으로 관리한다.
