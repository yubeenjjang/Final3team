## 1. 현재 확인된 것

| 단계 | 현재 상태 | 근거 |
|---|---|---|
| 문서 준비 | 사람이 확인한 제목·공식 URL·축제 ID·효력기간과 본문 항목을 입력받아 청크로 나누고 `pending` 적재 가능 | `backend/agents/rag/ingest_pending.py` |
| 검색 | `approved`·축제 ID·효력기간·임베딩 모델/버전이 맞는 청크만 조회 | `backend/agents/rag/search.py` |
| 승인 상태 필터 | 별도 `rag_scratch`에서 `pending → approved → rejected`의 비노출→노출→비노출 재현 | `backend/agents/rag/check_pgvector_sample.py`, RAG 샘플 기록 |
| 답변 | 짧게 바꿔 쓴 공식 안내 샘플 11문항의 답변/보류 검증 | `backend/agents/rag/evaluate_answers.py` |
| 관리자 승인 | `approved_by`·`approved_at` 스키마는 있으나 공식 RAG 문서 승인 API·인증·감사 기록은 미구현 | DB 001 스키마, 관리자 라우터 |

## 2. 실제 연결 시 지킬 계약

1. **수집 후보:** 공개 축제 ID, 공식 원문 URL, 발행 기관, 제목, 확인된 게시 시각, 효력 시작·끝, 수집 시각, 본문 항목, checksum을 묶어 `pending`으로 저장한다. 게시 시각을 알 수 없으면 추정하지 않는다. 날짜만 있는 종료일은 다음 날 0시 KST를 배타적 상한으로 저장한다. URL이나 모델 출력만으로 공식성을 승인하지 않는다.
2. **사람 검토:** 원문이 해당 축제의 안내인지, 출처가 공식인지, 내용·효력기간·기존 승인본과 충돌하지 않는지 확인한다. 승인/거절 요청자는 서버가 검증한 JWT와 `profiles.role`로 판정한다. 요청 문장 속 “관리자” 표현은 권한이 아니다.
3. **승인 기록:** 승인 시 `approval_status='approved'`, `approved_by`, `approved_at`을 같은 트랜잭션에서 기록한다. 이미 처리된 문서를 중복 승인하거나 검토 도중 문서 내용이 바뀌면 거절한다. 개정본은 새 checksum·문서 ID로 `pending` 적재하고 기존 승인본의 종료·대체 기준을 결정한 뒤 공개한다.
4. **검색:** 선택한 공개 축제 ID, 기준 시각, `text-embedding-3-small`·1024차원·임베딩 버전을 전달한다. 검색 결과에는 문서 ID·출처 URL·발행 기관·게시/효력 시각·청크 ID·본문을 함께 보존한다. `pending`·`rejected`·만료·다른 축제 문서는 답변 근거로 전달하지 않는다.
5. **답변:** 검색 결과가 없거나 출처가 충돌하면 확인 불가로 끝낸다. 정적 공식 안내로 현재 혼잡·날씨·경로를 답하지 않는다. 답변에 채택한 문서 URL과 확인 시각을 표시하고, 선택 축제와 질문 속 축제명이 다르면 재선택을 요청한다.

## 3. API·DB 담당자와 확정할 항목

| 결정 | 제안 | 확정 전 구현 경계 |
|---|---|---|
| 관리자 API 경로·권한 | 기존 관리자 인증 체계에 문서 목록·상세·승인·거절을 추가. 승인 요청에는 문서 ID와 검토한 checksum을 포함 | 공개 챗봇/수집기가 승인 상태를 직접 바꾸지 않음 |
| 승인 쓰기 권한 | 현재 `noldaga_service`는 DB 테이블에 폭넓은 쓰기 권한이 있으므로 API의 관리자 인증이 1차 경계. DB 차원의 별도 제한·감사 방식은 R03과 결정 | `noldaga_app`에 RAG 승인 쓰기 권한을 열지 않음 |
| 개정본 대체 | 새 승인본이 기존본을 대체할 때 기존 `effective_to` 또는 승인 상태를 원자적으로 변경할지 결정 | 상충하는 두 승인본의 날짜를 모델에게 동시에 확정 근거로 주지 않음 |
| 운영 검색 호출 위치 | W27 검색 함수를 백엔드 서비스에서 호출하고, W59 챗봇 연결 시 Supervisor→Festival 입력 계약에 맞춤 | 현재 샘플 평가기를 운영 API로 노출하지 않음 |
| 수집 방식 | 공식 사이트별 허용 범위·원문 구조 확인 후 수동 검토 또는 제한된 수집 어댑터 선택 | 임의 URL을 자동 크롤링·승인하지 않음 |

## 4. 수용 시험

- 승인 전 문서가 검색되지 않고, 관리자가 승인한 문서만 선택 축제의 유효기간 안에서 검색된다.
- 거절·만료·다른 축제·다른 임베딩 버전 문서는 제외된다.
- 관리자 권한이 없는 승인 요청은 실패하고 문서 상태·`approved_by`·`approved_at`이 바뀌지 않는다.
- 승인 뒤 같은 URL의 개정본이 들어오면 먼저 `pending`이며, 기존본과 날짜가 충돌할 때 답변은 보류한다.
- 근거가 없는 질문, 당일 혼잡·날씨 질문은 정적 RAG 답변으로 확정하지 않는다.

현재 별도 시험 DB의 10/10과 11문항 답변 시험은 **검색 필터와 샘플 판단의 부분 검증**이다. 위 관리자 권한·개정본·운영 API 수용 시험 결과로 대체하지 않는다.
