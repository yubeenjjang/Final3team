# W27 공식 문서 승인·검색 연결 계약 초안

> 2026-11-26, `dayoung` 검색 코드와 `ohyun 4f81832`의 관리자 승인 API 계약 대조. 기획서 FR-K01~K05, WBS W27, DB 001·009·029 스키마를 기준으로 한다. 승인 API는 `ohyun` 브랜치에 구현됐고, 이 문서 작성 시점에는 `main`에 병합되지 않았다. 실제 서비스 연결 완료로 해석하지 않는다.

## 1. 현재 확인된 것

| 단계 | 현재 상태 | 근거 |
|---|---|---|
| 문서 준비 | 사람이 확인한 제목·공식 URL·축제 ID·효력기간과 본문 항목을 입력받아 청크로 나누고 `pending` 적재 가능 | `backend/agents/rag/ingest_pending.py` |
| 검색 | `approved`·축제 ID·효력기간·임베딩 모델/버전이 맞는 청크만 조회 | `backend/agents/rag/search.py` |
| 승인 상태 필터 | 별도 `rag_scratch`에서 `pending → approved → rejected`의 비노출→노출→비노출 재현 | `backend/agents/rag/check_pgvector_sample.py`, RAG 샘플 기록 |
| 답변 | 짧게 바꿔 쓴 공식 안내 샘플 11문항의 답변/보류 검증 | `backend/agents/rag/evaluate_answers.py` |
| 관리자 승인 | 오현님 `ohyun 4f81832`에서 A83~A85 목록·상세·승인/반려 API, 운영자 권한·checksum 검사·이력·개정본 효력 종료 구현. 실제 서비스 검색과 연속 호출은 병합 후 확인 | `backend/api/routers/admin/rag_documents.py`, DB 029, 인계 현황표 1-3절 |

## 2. 실제 연결 시 지킬 계약

1. **수집 후보:** 공개 축제 ID, 공식 원문 URL, 발행 기관, 제목, 확인된 게시 시각, 효력 시작·끝, 수집 시각, 본문 항목, checksum을 묶어 `pending`으로 저장한다. 게시 시각을 알 수 없으면 추정하지 않는다. 날짜만 있는 종료일은 다음 날 0시 KST를 배타적 상한으로 저장한다. URL이나 모델 출력만으로 공식성을 승인하지 않는다.
2. **사람 검토:** 원문이 해당 축제의 안내인지, 출처가 공식인지, 내용·효력기간·기존 승인본과 충돌하지 않는지 확인한다. 승인/거절 요청자는 서버가 검증한 JWT와 `profiles.role`로 판정한다. 요청 문장 속 “관리자” 표현은 권한이 아니다.
3. **승인 기록:** A85 `POST /api/v1/admin/rag-documents/{document_id}/review`에 `decision`(`approve`/`reject`)과 검토한 `checksum`을 보낸다. 반려에는 `reason`이 필수다. 서버가 로그인한 운영자 ID·시각을 `approved_by`·`approved_at`으로 기록하고 `rag_document_events`에 이력을 남긴다. 이미 처리·checksum 불일치·빈 조각은 409로 거절한다. 같은 축제·원문 URL의 개정본을 승인하면 기존 승인본 `effective_to`를 새 문서 `effective_from`(없으면 승인 시각)으로 닫는다.
4. **검색:** 선택한 공개 축제 ID, 기준 시각, `text-embedding-3-small`·1024차원·임베딩 버전을 전달한다. 검색 결과에는 문서 ID·출처 URL·발행 기관·게시/효력 시각·청크 ID·본문을 함께 보존한다. `pending`·`rejected`·만료·다른 축제 문서는 답변 근거로 전달하지 않는다.
5. **답변:** 검색 결과가 없거나 출처가 충돌하면 확인 불가로 끝낸다. 정적 공식 안내로 현재 혼잡·날씨·경로를 답하지 않는다. 답변에 채택한 문서 URL과 확인 시각을 표시하고, 선택 축제와 질문 속 축제명이 다르면 재선택을 요청한다.

| 결정 | 제안 | 확정 전 구현 경계 |

## 4. 수용 시험

- 승인 전 문서가 검색되지 않고, 관리자가 승인한 문서만 선택 축제의 유효기간 안에서 검색된다.
- 거절·만료·다른 축제·다른 임베딩 버전 문서는 제외된다.
- 관리자 권한이 없는 승인 요청은 실패하고 문서 상태·`approved_by`·`approved_at`이 바뀌지 않는다.
- 승인 뒤 같은 URL의 개정본이 들어오면 먼저 `pending`이라 검색되지 않는다. 개정본 승인 후에는 효력 경계 직전에는 기존본만, 경계부터는 개정본만 검색된다. 출처·날짜가 실제로 충돌하는 다른 공식 문서들은 답변 단계에서 보류한다.
- 근거가 없는 질문, 당일 혼잡·날씨 질문은 정적 RAG 답변으로 확정하지 않는다.

현재 별도 시험 DB의 10/10과 11문항 답변 시험은 **검색 필터와 샘플 판단의 부분 검증**이다. 위 관리자 권한·개정본·운영 API 수용 시험 결과로 대체하지 않는다.

**오현님 구현 대조(2026-11-26):** `ohyun 4f81832`의 PostgreSQL 시험은 승인 전 비노출→승인 후 노출, 권한 없는 승인 거절, 반려, checksum 변경 409, 개정본 승인 전후 효력 경계를 자체 SQL로 검사한다. `dayoung`의 `search_festival_evidence`는 같은 `approved`·축제 ID·효력기간·모델/버전 조건을 사용한다. 운영 DB의 `document_id`·`chunk_id`는 UUID이므로 검색 결과에서는 문자열로 정규화해 답변 `citation_ids`와 연결한다. 이 형식 연결은 단위 시험으로 확인했다. **A85 API를 호출한 뒤 동일 실제 DB에서 우리 검색 함수와 답변 생성까지 이어간 시험은 아직 없다.** API가 `main`에 병합되고 DB 029가 적용되면 승인 전·후·개정판·거절·권한 오류를 같은 DB에서 재검증한다.
