| 강사 요구 | 현재 설계 위치 |
|---|---|

## 3. 강사가 요청한 "한 장 정리" 초안 (관점 7절의 5가지) — 월요일 확인용
1. **사용자 장면과 실패 하나:** 축제가 끝나고 귀가자가 동시에 "귀가 경로 조회"를 누름 → **우리 경로 처리 부분에 요청이 몰려 p95 지연·시간 초과가 늘어남**(외부 길찾기 API가 아니라 팀이 통제하는 내부 처리, 부하는 모의 공급원에만).
2. **역할별 판단·인계:** 코드(감지: p95·대기열·시간 초과율 기준 넘으면 사건 생성) → **Diagnosis**(지표·로그로 원인 후보: 중복 요청 폭주 / 대기열 포화 / 1차 공급원 오류, 근거와 모르는 점) → **Recovery**(allowlist 안에서 조치 선택·근거·포기 조건) → 코드(정책 검사·실행) → 같은 부하 재측정 → 판정. 인계 형식: A15 사건 상세(7-2), A18 허용 조치(7-9), A19 결정(7-4).
3. **대응과 막을 행동:** 묶기·대기열 조정·유효 캐시·2차 공급원·안전 축소·원복. **막을 것:** 목록 밖 조치, 목적지가 다른 요청에 비슷한 캐시 제공, 무제한 재시도, 카카오 결과 저장·캐시.
4. **확인 결과(정상·실패·조치 후 실패):** 구간별 p50·p95·오류율·**유효 경로 제공률**(검증된 경로가 담긴 응답 ÷ 보낸 요청), 감지 시간, MTTR, `final_mode`. B0·B1·A1을 같은 입력으로.
5. **모르는 것·담당·시점:** 조치 효과(G3 작은 실험) · 기준 숫자(평소 구간 측정 뒤) · 에이전트 실패 처리(G1·G2) · 보조 시험 범위(G5) — 3절의 담당·날짜는 월요일에 정함.
