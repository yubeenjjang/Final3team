### 1-2. A42·A81 화면 연동

- A42는 서버가 계산한 `score` 순서로 표시합니다. `sources`는 해당 점수에 반영된 출처이며, `signal: no_signal`은 네이버 점수가 없는 상태로 구석구석 점수는 표시할 수 있습니다. 응답 또는 항목이 `partial_sources: true`이면 해당 위치에 '일부 출처만 반영'을 표시합니다. `status: stale`이면 마지막 성공 목록과 기준 시각(`crawled_at`)을 표시합니다. 시작 전 축제에는 '곧 시작'을 표시할 수 있습니다.
- A81은 축제 상세에 최신 글을 기본 5건까지 보여 줍니다. 글마다 출처를 표시합니다. 블로그·뉴스는 축제 시작 30일 전 이후의 글을 선별하고, 카페는 제목 정확 일치 조건만 적용합니다. 카페 글의 `published_date`는 `null`이며 원문 링크로 제공합니다. `status: ok`의 빈 목록은 표시할 글이 없는 경우입니다. `status: unavailable`의 빈 목록은 조회 실패이며 `retryable: true`일 때 다시 시도할 수 있습니다. [API 설계문서 7-15](../API_설계문서.md)

## 2. 귀가 조회 상태값 — 화면이 구분해야 할 것

동기 200은 받은 경로를 바로 표시합니다. 202는 `status_url`과 `route_access_token`으로 상태를 조회합니다.

| `route_status` | 뜻 | 화면 | `completed_valid_route` |
|---|---|---|---|
| `queued` · `processing` | 접수됨·찾는 중 | 로딩, `retry_after_s`(2초)마다 다시 조회 | false |
| `ready` | 경로 있음 | 카카오 지도에 경로를 그리고 **출처(`provider`)·조회 시각(`queried_at`)** 표시(4절) | **true** (이때만 '성공') |
| `unavailable` | 공급원이 답을 못 줌 | `error.message` + `notices`(공식 안내) | false |
| `timed_out` | 시간 초과 | 같음 + 다시 시도 버튼(`retryable`) | false |
| `rejected` | 요청이 많아 거절(접수 단계 503) | "잠시 뒤 다시" | false |

## 4. 공급원 구분 — 꼭 지킬 규칙 (강사 피드백 API 2)
| `provider_tier` | 공급원 | 받는 방법 | 다시 보기 |
|---|---|---|---|
| `primary` | TMAP | 200(바로) 또는 202 → 상태 조회 | 결과 보존 시간 안에는 A05로 다시 조회 가능 |
| `secondary` | 카카오맵 | **200(접수 응답) 안에서만** | ❌ 저장 불가 → 다시 보려면 **새로 요청**. A05로 다시 부르면 `ROUTE_SECONDARY_SYNC_ONLY` |
| `mock` | 모의 서버 | 둘 다 | 가능 |
- **11/24 팀 결정** — TMAP Free 하루 10건(오류 포함)을 유지하고, 한도에 도달하면 카카오 2차(하루 1,000건)를 사용합니다. 부하 시험은 모의 응답을 사용합니다.
- 11/24 팀 결정으로 TMAP 경로를 카카오 지도 위에 그립니다(①). 카카오는 11/20 공식 답변에서 타사 지도 위 표시를 허용했고, SK는 회신이 없습니다. 경로 아래에 **경로 정보: TMAP**을 표시합니다.
- SK가 금지 회신하면 TMAP 경로를 소요 시간·환승·정류장 목록으로 표시합니다.
- 실제 모드에서는 TMAP의 운행 종료 후보를 제외하고 남은 후보만 표시합니다. 카카오 후보는 `service_running=null`이며 '막차 확인 불가'는 `notices`에 들어갑니다.
- 화면은 `secondary` 결과를 받으면 **그 화면에서 바로 그리고**, 새로고침·뒤로가기 뒤에는 '다시 조회' 버튼을 보여 주세요(같은 결과를 다시 불러올 수 있다고 안내하지 않기).
- 시연에서는 화면 구석의 **'모의 데이터' 표시(`is_mock`)**로 모의/실제 구간을 구분합니다.
