# W28 Festival Agent 자기 성찰 시험 준비

> 2026-11-26 준비본. 근거: `Docs/Step 1/놀다가_WBS.md` W28~W30, 단일 Festival Agent 설계서 3·4장, 11/27 강사 피드백. 아래 사례는 **시험용 고정 응답**이며 실제 축제 데이터나 구현 완료 결과가 아니다.

## 1. 대표 사례: 잘못 고른 후보의 근거를 다시 판단

동일 질문·동일 기준 시각으로 수정 전후를 비교한다. 질문은 “2026-11-26에 진행 중인 서울의 시험 축제 F01 상세를 알려줘”로 고정한다. F01·F02는 시험용 ID다.

| 순서 | 도구 응답·판단 | 기대 기록 |
|---|---|---|
| 첫 조회 | `get_festival(F01)`에 성공했지만 본문 `festival_id=F02`, 출처 `tourapi`, 갱신 시각 포함 | F02를 답변 근거에서 제외. `id_mismatch`와 첫 근거·판단 이유 기록 |
| 재확인 | 원래 이름·지역·날짜·진행 상태를 유지하여 `search_festivals(q="시험 축제", region="SEOUL", date_from="2026-11-26", date_to="2026-11-26", status="ongoing")` | 후보 ID, 진행 날짜, 출처, 갱신 시각을 다시 평가. 통신 오류 때문에 같은 호출을 반복한 경우와 구분 |
| 수정 조회 | 검증된 F01만 `get_festival(F01)`로 다시 조회 | 반환 ID·이름·출처·갱신 시각·진행 날짜가 원래 질문과 맞을 때만 답변 |
| 종료 | 재확인해도 ID·출처·시각이 어긋나거나 호출/시간 한도 소진 | `unavailable` 또는 이미 검증된 내용만 `partial`; F02를 F01로 설명하지 않음 |

비교 대상은 **첫 후보를 그대로 사용한 결과(B0)**와 **근거를 검토하고 다른 확인 경로로 수정한 결과(A1)**다. 같은 입력·고정 응답·도구 예산으로 실행한다. 성공은 최종 문장만 자연스러운지가 아니라 원래 요청 조건과 축제 ID·출처·시각이 모두 맞는지로 판정한다.

## 2. 별도 사례: 검색 조건 완화 규칙

`status=ongoing` 검색 0건 뒤 `status=ongoing,upcoming`으로 한 번 넓히는 것은 **규칙 기반 재검색**으로 따로 기록한다. “오늘 진행 중”이라는 질문에는 `upcoming` 결과가 나와도 성공으로 세지 않는다. 사용자 이름·지역·날짜 조건은 유지한다. 이 사례는 대표 자기 성찰의 성공 건수에 합산하지 않는다.

## 3. 구현 전에 고정할 계약

- 판단 입력: 원질문, 기준 시각, 요청한 축제 ID·이름·지역·날짜·상태, 첫 도구 결과의 ID·출처·갱신 시각, 남은 호출/시간 예산.
- 판단 출력: `accept` / `recheck` / `abstain`, 사유 코드(`id_mismatch`, `source_missing`, `time_missing`, `condition_mismatch`, `budget_exhausted`), 채택/제외한 근거 ID, 다음 도구 호출의 이름·인자.
- 재확인 호출은 Festival Agent 허용 도구 안에서만 한다. 기존 그래프의 전체 4회 호출·30초 협력적 제한을 넘기지 않는다. 늦게 도착한 성공 응답은 사용하지 않는다.
- 근거 검증은 코드가 최종 판정한다. 모델의 자기 성찰은 첫 결과의 문제를 설명하고 재확인 경로를 고르는 과정으로 추적한다. 모델이 없는 규칙 검사만 통과하면 자기 성찰 성공으로 기록하지 않는다.
- 첫 결과·판단 이유·수정 호출·최종 결과·호출 수·경과 시간·모델/토큰 비용을 한 `run_id`로 묶는다. 실제 모델/추론 설정은 실행할 때 기록한다.

## 4. W29 측정표와 인수 조건

| 필드 | 기록할 값 |
|---|---|
| 질문·조건 | 입력 문장, 기준 시각, 축제 ID/지역/날짜/상태 |
| 첫 결과 | 도구·인자, 반환 ID/출처/시각, 검출한 오류 |
| 자기 성찰 | 모델 판단·사유, 수정된 호출 또는 보류, 판단에 쓴 근거 |
| 종료 | `answered`/`partial`/`unavailable`, 최종 근거, 조건 충족 여부 |
| 비용·한도 | 호출 수, 실제 경과 시간, 모델 ID·토큰·비용, 예산 종료 여부 |

최소 수용 사례는 ① 잘못된 F02 응답을 기각하고 검증된 F01로 바로잡기, ② 재확인 결과도 틀려 보류하기, ③ 처음부터 올바른 F01은 불필요한 재확인 없이 답하기, ④ 4회/30초 한도에서 안전 종료하기다. 각 사례의 B0/A1을 같은 고정 입력으로 비교한다. 외부 API 실패 뒤 동일 요청을 한 번 더 보내는 기존 통신 재시도는 별도 시험으로 남긴다.

## 5. 현재 상태와 다음 연결

기존 Festival LangGraph에는 `interpret → check_slots → select_tool → call_tool → validate`와 통신 재시도·예산 종료가 구현돼 있다. 아래 선행 구현은 별도 선택 경로이며, W28(12/01~12/03)의 실제 모델 판단과 W29 측정 및 W30 결과서에는 실행 출력과 코드 커밋을 연결해야 한다.

**11/26 선행 구현:** `backend/agents/self_reflection.py`에 상세 결과 검토→모델 판단 주입→원조건 검색→선택 ID 상세 재조회 흐름을 별도 실행기로 구현했다. `backend/tests/agents/test_self_reflection.py`는 고정 응답으로 ID 오류 수정, 반복 오류 보류, 예정 축제 기각, 정상 결과의 불필요한 재조회 방지, 호출 상한, 잘못된 모델 승인 기각을 검사한다. Windows Python 3.12에서 에이전트 시험 **58개 통과**는 모델 판단을 고정 함수로 대체한 단위 시험 결과다. **실제 LLM 판단, 기존 LangGraph 노드 연결, W29 지연·토큰 측정은 아직 남아 있다.** 따라서 이 결과를 12/4 자기 성찰 시험 완료로 집계하지 않는다.

**추가 선행 연결(11/26):** `build_festival_graph(..., reflect_judge=..., as_of=...)`를 명시적으로 사용할 때만 상세 요청이 `reflect_detail` 노드로 간다. 기존 호출은 변하지 않는다. 고정 판단 함수를 넣은 LangGraph 흐름에서 F02를 기각하고 원조건 검색→F01 재조회가 이어졌으며, 입력 조건 누락·판단 실패는 안전 종료했다. Windows Python 3.12 에이전트 시험 **62개 통과**. 현재 `reflect_detail`은 내부 재확인 과정을 한 노드에서 수행하므로, W29에서 단계별 추적과 실제 모델 지연·비용을 기록할 때 노드 분리 또는 명시적 실행 기록이 더 필요하다. **실제 LLM 판단과 팀 공통 실행기·운영 API 연속 시험은 아직 수행하지 않았다.**
