# 놀다가 요구사항·시험 상세 명세

기획서 제출본에서 분리한 세부 요구사항·시험 항목이다. 아래 절 번호와 일정·상태 문구는 분리 전 원문을 보존한 것으로, 현재 제품 범위와 우선순위는 기획서 4장, API·DB 계약은 Step 2 설계서, 작업 상태는 WBS를 따른다.

### 4.18 신규 요구사항 — 맞춤형 축제 추천 (FR-REC)

FR-REC01~18은 모두 필수(Must) 요구사항이다. 축제 발견 추천·지금 핫한 축제·요즘 올라온 글은 경로(FR-R)·방문 코스(FR-P)·AI 챗봇(FR-C)과 구분한다. 사용자의 취향 선택은 선택 사항이지만 서비스 구현은 필수다.

| ID | 기능 요구사항 | 우선순위 | 수용 기준 |
|---|---|---|---|
| FR-REC01 | 최초 로그인 취향 온보딩 | Must | `취향 선택하기/건너뛰기` 제공, 첫 설정 후 매 로그인 강제 반복 없음 |
| FR-REC02 | 취향 카드 5종 | Must | 가족·친구·연인·반려견과 함께하는 축제·혼자 상황 설명·대표 이미지, `이전/다음/선택/해제/건너뛰기` |
| FR-REC03 | 복수 취향 선택 | Must | 여러 취향 동시 선택; 반려견과 함께하는 축제는 하나의 취향으로 저장, 스와이프만으로 자동 선택 금지 |
| FR-REC04 | 취향 저장·건너뛰기 | Must | 사용자 계정에 취향 및 온보딩 상태 저장; 무선택 완료는 건너뛰기와 동일 |
| FR-REC05 | 취향 재설정 | Must | 추천 화면과 `마이페이지 → 나의 축제 취향`에서 수정, 변경 시 재계산 |
| FR-REC06 | 맞춤형 축제 사진 카드 | Must | 추천 이유·사진·축제명·기간·장소·상태 표시, 카드 선택 시 기존 상세 연결, 사진 없으면 기본 이미지 |
| FR-REC07 | 전국 추천 전체보기 | Must | 기존 축제 목록 UI·페이지·지역/날짜/상태 필터 재사용, 취향 미선택 지역 자동 배제 금지 |
| FR-REC08 | 검증된 규칙 기반 추천 | Must | 승인·게시된 예정/진행 축제 중 태그 일치·날짜 적합도·정보 완성도·관심 저장 보정으로 점수 계산 |
| FR-REC09 | 추천 이유·동반 가능성 검증 | Must | 공식 근거·검증된 태그만 속성으로 사용; 반려견 동반 가능·한가로움 등 임의 단정 금지 |
| FR-REC10 | 인기 축제 | Must | 최근 7일 상세 조회·관심 저장 등 실제 집계 기준으로 정렬, 봇/중복 방지·동률 고정 정렬 |
| FR-REC11 | 전체 축제 일부 둘러보기 | Must | 전국 공개 축제를 일부 섞어 표시, 하루/세션 고정 시드로 목록과 페이지 순서 안정화 |
| FR-REC12 | 지역별 전체 축제 보기 | Must | `전국` 기본 + 17개 시·도·기간/상태 필터, 기존 A02 `GET /api/v1/festivals` 활용 |
| FR-REC13 | 최신 등록 축제 | Must | `festivals.published_at` 최신순. 수정·재수집으로 최초 공개일 변경 금지 |
| FR-REC14 | 관심과 취향의 관계 분리 | Must | 추천되었다고 자동 관심 저장하지 않음, 관심 저장은 기존 인증/권한 기준 적용 |
| FR-REC15 | 빈 상태·오류·부분 장애 | Must | 취향 건너뛰기는 배너, 일치 축제 없음은 전체보기, 추천 API 오류여도 기본 축제 탐색 유지 |
| FR-REC16 | 사용자 정보 보호·접근권한 | Must | 사용자 취향은 본인만 조회/변경 가능, 정해진 보존·탈퇴 처리 준수 |
| FR-REC17 | 지금 핫한 축제 | Must | 게시된 진행 중·30일 이내 시작 축제를 네이버 데이터랩 검색 관심 증가율과 대한민국 구석구석 인기순으로 정렬하고, 출처 부족·조회 불가를 구분. 상세 산식과 상태는 5.18절 A42 참조 |
| FR-REC18 | 요즘 올라온 글 | Must | 축제 상세에 네이버 블로그·뉴스·카페 검색 결과의 제목·링크·출처를 표시. A42 순위에는 사용하지 않으며 게시일·캐시 규칙은 5.18절 A81 참조 |

**축제 탭 4개 영역:** 맞춤형 축제·인기 축제·전체 축제·최신 등록. A42 지금 핫한 축제는 추천 기능의 세부 목록이며 기존 4개 영역은 유지한다. 인기 지표가 부족하면 대체 목록과 안내를 제공하며 실제 지표를 임의 생성하지 않는다. **'취향 기반 축제 발견'은 기존 'AI 방문 코스 추천(FR-P01~03)'과 각각 유지한다.**

### 4.19 신규 요구사항 — 동행 찾기·친구·채팅 (FR-COM)

FR-COM01~24는 동행 모집·친구·1:1/단체 채팅을 포함한 필수(Must) 요구사항이다. 세부 범위는 4.20을 따른다.

| ID | 기능 요구사항 | 우선순위 | 수용 기준 |
|---|---|---|---|
| FR-COM01 | 축제별 동행 모집 목록 | Must | 기존 `festival_id`에 연결된 모집 글·만남 일정·조건·승인 인원·모집 상태 조회 |
| FR-COM02 | 모집 글 작성 | Must | 로그인 사용자만 등록, 축제 자동 연결, 날짜·시간·희망 연령대/성별·정원·메모 입력 |
| FR-COM03 | 모집 일정·조건 검증 | Must | 축제 기간 내 미래 시각만 허용, 추가 모집 인원은 작성자 제외 기준, 부적절 입력 제한 |
| FR-COM04 | 모집 글 생성과 동행방 연결 | Must | 게시 시 작성자만 입장한 `companion` 방 생성, 만남 장소는 최초 `미정` |
| FR-COM05 | 신청·취소 | Must | 로그인 사용자가 짧은 메시지로 신청, 승인 전 취소 가능, 본인 글·중복 신청 금지 |
| FR-COM06 | 작성자 승인·거절 | Must | 작성자만 신청 처리. 승인된 사람만 방 입장·정원 반영, 동시 승인으로 정원 초과 방지 |
| FR-COM07 | 모집 마감 | Must | 정원 도달 시 모집 마감·추가 신청 거절, 종료/취소와 상태 구분 |
| FR-COM08 | 동행방 권한 | Must | 작성자와 승인된 참여자만 메시지·정확한 만남 장소 조회. 임의 친구 초대 금지 |
| FR-COM09 | 동행방 단체 메시지 | Must | 텍스트/시스템 메시지 전송·조회·시간순 표시, 권한 검증 실패 시 전송/구독 차단 |
| FR-COM10 | 만남 장소 확정 | Must | 작성자가 지도 검색/핀으로 장소명·주소·좌표·안내 등록, 상단 카드·지도 표시 |
| FR-COM11 | 만남 장소 변경 | Must | 작성자만 변경, 변경 시각 기록·시스템 메시지·참여자 알림; 지도 오류 시 텍스트 제공 |
| FR-COM12 | 친구 검색·신청 | Must | 대소문자를 무시한 닉네임 정확히 일치 검색, 친구 요청·취소·거절·수락·목록, 연락처 기본 공개 금지 |
| FR-COM13 | 친구 관계의 독립성 | Must | 동행 참가·승인만으로 친구 자동 추가 금지, 상대방 수락 후 관계 성립 |
| FR-COM14 | 친구 삭제·차단 | Must | 관계 삭제와 상호/단방향 차단에 따른 새 메시지·초대·조회 권한 검사 |
| FR-COM15 | 친구 1:1 채팅 | Must | 실제 친구 관계 확인 후 방 생성·대화, 동행 종료와 독립적으로 유지 |
| FR-COM16 | 친구 단체 채팅 | Must | 친구 2명 이상 선택·방 이름 지정·초대, **초대 수락 후 입장**·입장 이후 메시지 표시 |
| FR-COM17 | 친구방 운영 | Must | 방장 이름 변경·추가 초대, 사용자 자진 퇴장, 방장 퇴장 시 권한 승계 |
| FR-COM18 | 동행 종료/취소 | Must | 작성자 종료 또는 정책에 따른 만남 시각 후 자동 종료, 사전 취소는 별도 상태·알림 |
| FR-COM19 | 지난 동행 | Must | 종료된 동행방은 지난 동행으로 이동·읽기 전용, 장소/메시지는 보존 정책 내 열람 |
| FR-COM20 | 채팅 탭 목록·빈 상태 | Must | 전체·동행방·친구 채팅·지난 동행 필터, 방이 없을 때 동행/친구 기능 안내 |
| FR-COM21 | 신청·친구·방·장소 알림 | Must | 신청/승인/거절·친구 수락·초대·장소 변경 등 앱 내 알림과 읽음 처리; 외부 푸시는 별도 확정 |
| FR-COM22 | 마이페이지·프로필 | Must | 내 모집 글/신청 내역·프로필·설정, 개인정보 최소 노출 |
| FR-COM23 | 신고·차단·운영 | Must | 모집 글·채팅 악용 신고, 차단과 부적절한 메시지 처리, 관리 권한·기록 |
| FR-COM24 | 보안·탈퇴·데이터 처리 | Must | 인증, 방 멤버 자격, 전송/구독 권한, **동행 채팅 단기 보관 및 친구 채팅 기간 제한 보관 정책**·삭제·탈퇴 시 처리를 일관되게 적용 |

**방 종류·생명주기 및 보관 정책:** `companion`(모집 글 작성 시, 작성자+승인자, 종료 후 읽기 전용·**단기 보관**) / `direct`(친구 간 1:1, 관계 정책 준수·**기간 제한 보관**) / `friend_group`(친구 2명 이상 초대·수락 후 입장·**기간 제한 보관**). 저장 구조는 Redis 단기 보관·PostgreSQL 장기 이력으로 통일한다(5.20). 방별 보존 기간과 저장소 역할은 별개이며, 모든 방의 메시지는 승인된 보존 기간 내에서만 열람한다.

**신규 보안 경계:** 정확한 만남 장소와 동행 메시지는 승인된 멤버에게만 노출한다. 사용자 실명·전화번호·이메일·GPS 실시간 이동경로는 필수로 수집하지 않는다. 채팅은 **AI가 사용자 대신 대화하거나 자동으로 동행을 연결하는 기능이 아니며**, 기존 AI 챗봇과 별개다.

### 4.20 추가 기능의 필수 구현 범위

| 기능군 | 필수 구현 내용 | 연결 작업 |
|---|---|---|
| 맞춤형 축제 추천 | 취향 선택·건너뛰기·변경, 규칙 추천·근거, 인기·전체·최신 목록과 A42 지금 핫한 축제·A81 요즘 올라온 글, 빈 상태·권한 처리(FR-REC01~18) | W123~W128 |
| 동행 찾기 | 모집·신청·승인/거절·정원, 동행방 채팅(단기 보관)·만남 장소, 종료·취소·지난 동행 | W114~W117·W120·W122 |
| 친구·사용자 채팅 | 검색·친구 요청/수락·삭제·차단, 1:1·단체방(기간 제한 보관)·초대 수락·퇴장·방장 승계 | W118·W119·W121 |
| 공통 기반·검증 | 자체 JWT 인증·프로필·멤버 권한, 앱 내 알림·신고·차단·보존·탈퇴, REC-TC/COM-TC 전체 검증 | W112~W114·W116·W122·W128 |

**범위:** 추가 기능 2종과 위 세부 요구사항은 필수다. 사용자에게 이용을 강제한다는 뜻은 아니며, 기능을 사용하지 않아도 공개 축제 탐색과 귀가 안내는 이용할 수 있다. 인기 지표 부족 시 대체 목록을 표시하는 것은 필수 예외 처리이며 인기 집계·순위 기능의 제외를 뜻하지 않는다. 외부 푸시와 GPS 실시간 위치 공유는 이번 추가 범위에 포함하지 않는다.

**일정:** W112에서 R01은 화면·요구사항, R03은 API·DB·공수, R06은 기존 일정·가용 시간을 대조해 11/20까지 개발·검토·시험 일정안을 작성한다. 일정이 미확정이어도 필수 범위와 진행률 분모에는 포함한다. 공수 충돌 시 업무 재배정·병행 순서·일정을 조정하며 필수 기능을 자동 보류하지 않는다.


# 상세 시험 항목

### 8.3 테스트 공통 원칙 (대표 흐름)

- 전국 축제 플랫폼은 **실제 원천 기반 여러 지역의 축제**를 지도·검색·상세에 연결한다. 특정 한 행사만 플랫폼으로 하드코딩하지 않는다.
- **대표 기술 시연은 자체 Route Query Service에 대한 통제 부하**다. 사용자가 실제로 선택한 축제의 귀가 요청 흐름과 연결하되 외부 API(TMAP·카카오맵)를 고부하 공격하지 않는다. **현재 수행된 시험은 in-process ASGI 모의 처리 120건 burst 1회로, 이 대표 통합 시연과 구분**한다.
- 실제 실호출/모의 경로, 모의 장애/실제 장애, 내부 처리 병목/외부 공급원 오류, 단순 예측 경고/실제 장애를 **분리**한다.
- 동일한 `offered` 부하·요청 목적지 분포·지속시간·타임아웃·캐시 상태·인프라 조건에서 B0/B1/A1을 비교한다.
- **사용자가 실제 검증된 경로를 받은 것만 성공**이며 `accepted/queued`는 성공이 아니다. 사용자 안전·공식 통제도 데이터 확보 범위에서만 확정한다.
- 이전 `TC-30~34` 등의 혼잡 API 장애 시험은 **보조 시험으로 유지**하고 ID 재사용/삭제 없이 대표 귀가 부하 시험은 `RETURN-TC`를 신규 접두어로 사용한다.
- 테스트 합격 임계값과 실행 결과를 임의로 만들어 기입하지 않는다.

### 8.19 추가 기능 리스크·검증

아래는 맞춤형 축제 추천·지금 핫한 축제·요즘 올라온 글과 동행·친구·채팅의 필수 수용 시험이다. FR-REC01~18·FR-COM01~24 모두 필수 검증 대상으로 한다.

| 신규 리스크 | 필요한 통제·예외 처리 |
|---|---|

| 인기 순위 왜곡 | 집계 기준·기간 공개, 봇·중복 요청 완화, 지표 부족 시 임의 순위 대신 대체 목록 |
| 모집 악용·정원 초과 | 작성/신청/승인 권한 분리, 중복 방지, 동시 승인 트랜잭션, 취소/마감·과거 일정 검증 |

| 이용자 간 만남·대화 안전 | 신고·차단·부적절한 글 대응, 개인정보/연락처 노출 최소화, 만남 장소 변경 이력·신고 처리 경로 |

| 서비스 간 장애 확산 | 추천 또는 채팅 장애 시에도 기존 축제 목록·상세·AI 안심 귀가와 관리자 장애 시연은 격리 유지 |
