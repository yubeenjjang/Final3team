## 2. 일정 관리 기준

1. **진행률:** 검토·필요 시험을 통과한 필수 완료 작업 수 ÷ 118 × 100. W40·W43·W85·W92·W97·W107·W108·W109·W110·W111은 제외한다. 실제 완료 근거 확인 전 진행률은 산정하지 않는다.
2. **상태:** `할 일 → 진행 중 → 검토 중 → 완료`. 막힘·지연은 원인·영향·새 예상일을 함께 기록한다. 선택 작업의 채택 여부와 실제 진행 상태를 구분한다.
3. **선행·병행:** 선행 작업 완료 후 연결한다. 표의 기간이 겹치는 작업은 아래 인계표의 검토된 부분본으로만 병행하고 최종 검증은 선행 검증본 수신 후 수행한다.
4. **계획·실적:** 담당자는 실제 수행일·결과 링크·상태를 기록하고 R06이 취합한다. 기존 수행 상태는 확인된 근거에 따라 갱신하며, 설계·로컬 시험·AWS 적용·배포·제출을 구분한다.
5. **공수·지연:** R01·R03·R06은 11/20까지 W112에서 담당별 기존/신규 구현·검토·시험 시간을 합산한다. 초과 시 지원 분담·병행 순서·기간을 조정하고 간트·선행·마일스톤을 함께 갱신한다. 두 추가 기능은 필수로 유지하며 충돌이 해소되지 않으면 영향과 회복 계획을 기록한다.
6. **배포 기준:** 12/18 신규 기능 시험본 → 12/22 통합본 → 12/23 전체 E2E → 12/24 권한 재확인·배포. 차단 결함이 남으면 배포 완료로 판정하지 않는다. 이후에는 회귀·결함 수정·제출 준비를 수행한다.

## 5. 추가 필수 기능 작업 계획

**수량 구분:** 추가 기능은 ① 맞춤형 축제 추천 ② 동행·친구·채팅의 **2종**이다. 세부 요구사항은 추천 16개(FR-REC)·동행/친구/채팅 24개(FR-COM)로 나눈 **40개 항목**이며, 이를 구현·검증하는 WBS 작업은 W112~W128 **17개**다. 세 수치는 서로 다른 단위이고 기능을 40종으로 확장한 것이 아니다.

맞춤형 축제 추천(FR-REC01~16)과 동행·친구·채팅(FR-COM01~24)은 모두 필수다. 아래 날짜는 배포 전 통합·시험 시간을 확보하기 위한 계획이며 실제 착수·완료나 담당자의 공수 확인을 뜻하지 않는다.
