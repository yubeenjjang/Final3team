# 정기 작업 명세

저장소 루트에서 `PYTHONPATH=backend python -m api.jobs.scheduler`를 실행한다. 예약기는 이 명령을 시간마다 호출한다. 시각과 회차는 `Asia/Seoul` 기준이다.

| 작업 | 회차 | 기준과 처리 |
|---|---|---|
| `purge_route_results` | 매시 정각 | TMAP 결과를 조회 후 23시간부터 정리한다. 최초 삭제 시각과 요청 증빙은 기존 013 트리거에 기록한다. |
| `maintain_companions` | 매시 정각 | 기존 A65 동작을 사용한다. 수동 종료·취소 즉시 방은 읽기 전용이다. 자동 종료에서는 만남 시각에 `COMPANION_AUTO_END_H`(기본 12시간)를 더한 시각을 종료·읽기 전용 시각으로 기록한다. 이 시각에서 72시간이 지나면 메모·만남 장소·신청 메시지·채팅 본문을 정리한다. |
| `retention` | 매일 06:00 | DB 7-0 기준으로 접수 30일이 지난 경로 요청과 결과를 삭제한다. 사건 연결 요청은 장소 해시 두 칸을 NULL로 바꾼다. 삭제 대상에 걸린 공유 참조와 챗봇 이력의 경로 참조는 NULL로 전환한다. |
| `retention` | 같은 회차 | 90일이 지난 알림과 응답 후 30일이 지난 거절·취소 친구 신청을 삭제한다. 친구 채팅은 작성 후 30일, 동행방 채팅은 읽기 전용 전환 후 72시간이 지나면 본문을 NULL로 바꾸고 삭제 시각을 채운다. 메시지 행과 방별 순서는 남긴다. |
| `retention` | 같은 회차 | 7일이 지난 LangGraph 대화의 `thread_id`를 체크포인트·블롭·쓰기에서 함께 삭제한다. `checkpoint.ts`와 `assistant_runs`의 최근 실행 시각을 기준으로 삼는다. 첫 체크포인트가 남지 않은 저장은 연결된 실행 이력을 기준으로 판단한다. |
| `collect_festivals` | 매일 06:00 | `api.ingestion.festivals.collect`의 `--since <KST 올해>-01-01 --db` 수집 경로를 사용한다. DB의 A23 수집 이력을 저장하며 스케줄러는 파일 출력을 생략한다. |

정각 이후 실행할 경우 해당 시간 회차를 처리한다. 일일 작업은 당일 06:00 이후 첫 실행에서 시작하고, 같은 날 후속 호출에서 실패한 작업을 재시도한다. 작업별 성공 회차는 022의 `scheduled_job_runs`에 한 행으로 남긴다. PostgreSQL 트랜잭션 advisory lock을 잡은 후 기록을 확인한다. DB 정리와 회차 기록은 함께 커밋한다. 축제 수집은 기존 이력 트랜잭션을 사용하므로 수집 커밋과 회차 기록 사이에서 중단되면 재실행될 수 있다. 기존 축제 적재는 출처와 원본 ID로 중복을 처리한다. A23 `partial`도 일일 회차 실패로 보고한다.

작업마다 한 줄에 이름, 상태, 회차, 처리 건수와 소요 시간을 기록한다. 완료된 회차는 `already_done`, 실행 중인 작업과 경합하면 `locked`, 실패하면 `error`로 표기한다. 종료 코드 `0`은 모든 대상 작업 성공 또는 완료 상태, `1`은 실행 실패, `2`는 잘못된 CLI 인자, `3`은 잠금 충돌이다. 잠금 충돌과 실패가 함께 발생하면 `1`을 반환한다. 실패한 작업 뒤에 남은 작업도 실행한다.

실행 계정은 기존 `noldaga_service`다. LangGraph가 동일 DB에 설치되면 3개 테이블의 `SELECT`·`DELETE`와 스키마 `USAGE`를 기존 A80과 같이 부여한다. 세 테이블이 모두 없으면 체크포인트 정리 건수는 0이다. 체크포인트 저장과 테이블 잠금이 경합하거나 일부 설치 상태면 일일 정리 트랜잭션을 롤백한다. 체크포인트 시각과 연결된 실행 이력이 모두 없는 데이터는 만료 시각을 확인할 수 있을 때까지 보존한다.
