# W48 내부 귀가 과부하·복구 비교 기준 초안

- 작성: 2026-11-25, 기준 브랜치 `yubeen` `cf97634`
- 상태: **초안**. W96 로컬 중간본과 11/24 팀이 확정한 API 설계서 7-0·9-1을 대조했다. W49 감지·W50 실행 코드를 구현하거나 운영 장애 기준을 새로 승인한 기록은 아니다.
- 입력 근거: [W96 로컬 계측](../w96/VERIFY.md), `Docs/Step 2/API_설계문서.md` 7-0·7-3~7-5·9-1, `Docs/Step 2/handoff/오토힐링_강사자료_대조.md` G1~G6.

## 1. 감지·복구 기준

| 항목 | 초안 기준 | 근거·상태 |
|---|---|---|
| 장애 감지 | 귀가 조회 p95 **3초 초과**가 **30초 지속** | 11/24 팀 결정. W96 소표본만으로 변경하지 않음 |
| 정상 복구 | 귀가 조회 p95 **3초 이하**가 **5분 연속 유지** | 11/24 팀 결정. 순간적인 하락으로 종료하지 않음 |
| 원인 분류 | 전체 지연 외에 내부 p95·외부 p95·대기열·inflight·거절·시간 초과·고유 키 비율을 함께 기록 | 내부 과부하와 공급원 장애를 혼동하지 않기 위한 진단 입력. 세부 관측창 구현은 W49 |
| 조치 시간 | A19 기본 `stop_condition.max_minutes=5` | API 9-1의 임시값. 조치 제한과 정상 복구 유지 5분은 서로 다른 시계 |
| 설정 버전 | 비교 실행마다 현재 코드 커밋·설정값·`LIMITS_VERSION`을 기록 | `LIMITS_VERSION` 통합 코드는 아직 없음. 구현 전에는 값이 없는 사실을 그대로 기록하고, 설정 변경 때 버전 갱신 필요 |

30초 관측창에서 표본이 부족하면 p95만으로 자동 장애를 확정하지 않는다. 이때 요청 수·미종료·오류를 별도로 표시하고, 최소 표본 수는 W106의 부하 도구가 준비되면 비교 전에 고정한다. W96의 4~8건 p95을 3초 SLO의 합격 증거로 쓰지 않는다.

## 2. 조치 선택·중단 규칙

| 관측된 근거 | 후보 | 실행 전 확인 | 중단·원복 |
|---|---|---|---|
| 동일한 v2 `route_key` 요청이 반복되고 내부 지연이 주원인 | `singleflight_enable` | 같은 키만 공유, 통제 버전·출발/목적지·조건 일치. **현재 메모리 경로에는 `_flights`와 `_cache`가 기본 동작하므로 W96의 1/8 실행은 기본 최적화 효과다. 조치 토글과 독립 효과가 구현·측정되기 전에는 W50 복구 성과로 선택하지 않음** | 유효 완료율 개선 없음, 거절·시간 초과 증가 시 원복 |
| 고유 키가 많고 내부 큐가 쌓이며 외부 공급원 지연은 정상 | `bounded_queue_adjust` | 큐 깊이·대기 시간·허용 상한 근거 확인. 고유 키에는 묶기 효과를 기대하지 않음 | 거절 증가나 유효 완료율 악화 시 즉시 원복 |
| 정확히 같은 경로 조건의 유효 캐시 존재 | `valid_cache_serve` | `valid_until`·통제 버전·검증 시각 확인. **기본 캐시 적중을 새 복구 효과로 세지 않음** | 만료·통제 변경·검증 실패 시 즉시 중단 |
| `failure_domain=route_upstream`이며 1차 공급원 오류 확인 | `fallback_provider_switch` | 2차 키·실호출·남은 한도 확인. 내부 과부하만으로는 선택 금지 | 1차 회복 또는 2차 한도 80% 도달 시 중단. 카카오 결과 저장·캐시 금지 |
| 허용 조치가 없거나 조치 효과 없음 | `safe_degrade` | 경로 확인 불가를 명시하고 축제 검색·상세는 유지 | 정상 지표 연속 회복 뒤 종료. 경로를 제공한 성공으로 집계하지 않음 |

에이전트가 허용 목록 밖의 조치를 제안하면 정책 코드가 거부하고 이유를 사건에 남긴다. A1의 모델 시간 초과·형식 오류·금지 제안 시 B1 규칙으로 전환하되 **같은 사건의 남은 시간·시도 예산을 그대로 사용**한다. 실제 대응 주체(`responder_type`)를 `rule`로 남기고 A1의 순수 성과로 세지 않는다. W49·W50 구현 전까지 이 규칙은 실행되지 않는다.

## 3. 결과 지표의 계산법

- `offered` = 시험이 보낸 전체 요청 수. 접수 실패·429/503·시간 초과·시험 종료 때 미완료를 모두 분모에 포함한다.
- `valid_completed_rate` = 정한 완료 제한 시간 안에 검증된 경로를 받은 요청 수 ÷ `offered`. HTTP 202 접수, 경로 없는 200, `safe_degrade`, 늦은 완료는 분자에서 제외한다. 완료 제한 시간은 API의 현재 총 10초 값을 후보로 기록하고 W106 비교 전에 고정한다.
- `api_p95_ms` = 접수 API 응답 지연. `route_completion_p95_ms` = 유효 경로 완료 요청의 제출→완료 지연. 오류·거절·미종료 건수와 비율을 함께 제시해, 실패를 제외한 p95만 낮아져도 성공으로 판정하지 않는다.
- `duplicate_ratio` = 1 − 고유 v2 `route_key` 수 ÷ `offered` (`offered=0`이면 계산 불가). 목적지 문자열만 같은 경우가 아니라 정규화한 경로 조건이 같은 경우에만 중복으로 센다.
- `recovery_rate` = 정상 복구 사건 수 ÷ 시험 전에 정한 유효 장애 사건 수. 미복구·안전 축소·시험 중단을 분모에서 빼지 않는다.
- `MTTR` = 코드가 사건을 감지한 시각부터 **5분 연속 정상 조건이 끝난 시각**까지. 정상 복구 사건에 대해서만 평균·중앙값을 계산하고, 미복구 사건 수와 경과 시간을 별도 표기한다. 대기열 접수만으로 복구로 보지 않는다.
- `final_mode`는 `normal_recovered`, `valid_cache`, `alternate_source`, `degraded`, `unresolved`를 구분한다. 뒤의 세 상태를 정상 복구율에 합치지 않는다.

## 4. B0/B1/A1 비교 실행표 초안

| 고정할 입력 | 비교 규칙 |
|---|---|
| 대응군 | B0=사건 감지·기록만, B1=고정 규칙 선택, A1=Agent 제안 후 동일 정책 코드 검사. **기본 캐시·기본 `_flights`는 세 군에 동일하게 유지** |
| 부하 | 반복·고유 목적지, burst·지속, cold·warm을 각각 비교. 추가 혼합 중복률 30%·70%는 탐색 시험으로 따로 표시 |
| 동일성 | 같은 seed·요청 본문·제공 요청량·동시성·지속 시간·시험용 공급원 지연/오류·코드/설정 버전·CPU/워커·캐시 초기 상태를 세 군에 재현 |
| 순서·반복 | 순서 편향을 줄이도록 B0→B1→A1, B1→A1→B0, A1→B0→B1을 한 묶음으로 반복하는 안. 반복 수·요청 수·지속 시간은 W106 도구와 W96 재측정 후 **첫 정식 비교 전에** 확정 |
| 기록 | 구간별 `offered`, 유효 완료, API·완료 p95, 큐/inflight, 공급원 실행 수와 지연, 거절·오류·미종료, 감지/조치/원복 시각, `final_mode`, AI 호출 수·비용·실패·규칙 전환, 원본 결과 위치 |

`B1` 또는 `A1`이 B0보다 유효 완료율을 높이지 못하거나 거절·시간 초과를 늘리면 성공이라고 쓰지 않고 원복한다. A1은 B1보다 더 낫다는 결론을 미리 두지 않는다. 실제 외부 공급원에는 부하를 넣지 않고 `mock_adapter`로 내부 지연을 재현한다.

## 5. 사전 위험 예측의 시험 계약 초안

W49의 예측 입력은 **현재 시점까지** 관측한 offered RPS, 내부 p95, 큐 깊이·inflight, 거절·시간 초과 추세로 제한한다. 미래의 장애 판정, 조치 결과, 공급원 응답을 입력에 섞지 않는다. 정답은 이후 관측창에서 1절의 장애 조건이 처음 충족됐는지로 만든다. 예측 선행 시간, 적중·오경보·누락 건수를 함께 남기고 장애가 난 뒤의 탐지는 사전 예측 성공으로 세지 않는다. 예측 시야와 위험 임계값은 W106 시계열 시험 전에 고정한다. W96의 단일 실행 결과로 예측 품질을 주장하지 않는다.

## 6. 확정 전에 남은 결정과 인계

1. W106의 시험 도구가 요청 수·지속 시간·반복 수·30초 창의 최소 표본 수를 재현 가능하게 고정한다. W96의 소표본은 비교 입력 후보일 뿐 수용 기준이 아니다.
2. W49는 전체·내부·외부 지연과 큐를 구분해 감지 근거를 사건 ID에 기록하고 `LIMITS_VERSION`을 실제 설정과 연결한다.
3. W50은 기본 최적화와 **장애 뒤 켜는 조치**를 코드에서 구별한다. 토글 없는 `singleflight_enable`·`valid_cache_serve`는 복구 성과 시험에서 제외한다.
4. W44에 위 지표·조치 허용 조건·A1→B1 전환과 공유 예산을 인계한다. W51의 첫 비교 전에 W48 표의 미정값을 확정하고 버전·커밋을 고정한다.
