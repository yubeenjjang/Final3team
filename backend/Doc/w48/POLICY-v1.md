# W48 내부 귀가 과부하·복구 정책 및 비교 계약 v1

- 확정일: 2026-11-25. 적용 대상: 내부 귀가 경로 조회 과부하. W96의 로컬 계측과 API 설계서 7-0·7-3~7-5·9-1을 기준으로 한다.
- 이 문서는 W44·W49·W50·W51·W106의 입력 계약이다. 실제 자동 감지·조치와 B0/B1/A1 성능 결과는 해당 작업에서 검증한다.
- 아래 표본·반복·시야 값은 **비교 실험 설계값**이며 W96의 64개 로컬 요청에서 추정한 운영 성능값이 아니다. 변경 시 정책 버전과 사유를 기록하고 세 군을 모두 재시험한다.

## 1. 장애와 정상 복귀

| 항목 | 고정 기준 |
|---|---|
| 장애 감지 | 귀가 조회 완료 지연의 30초 관측창 p95가 **3초 초과**인 상태가 30초 유지될 때. 완료 지연과 별도로 오류·거절·미완료 수를 기록한다. |
| 관측 유효성 | 각 30초 창에 완료 지연 표본 **30개 이상**. 미달 창은 `insufficient_sample`로 표기하고 p95만으로 자동 감지·정상 판정하지 않는다. 거절·시간 초과는 별도 안전 신호로 처리한다. |
| 정상 복귀 | 유효한 연속 관측창에서 p95 **3초 이하가 5분 연속 유지**되고, 거절·시간 초과·유효 완료율이 장애 전 기준보다 악화되지 않았을 때. 순간 회복이나 접수 성공은 복귀가 아니다. |
| 원인 분리 | 내부 처리 p95, 외부 공급원 p95, 대기열 깊이·대기 시간, inflight, 거절·시간 초과, 고유 route key 비율을 같은 사건 ID로 기록한다. 외부 공급원 실패만으로 내부 과부하 조치를 실행하지 않는다. |
| 조치 제한 | 한 사건의 자동 조치 시도는 기본 최대 5분. 이 제한과 정상 복귀 확인 5분은 별도의 시계다. 제한 도달 시 추가 조치를 멈추고 미복구/안전 축소로 기록한다. |

기존 팀 합의값인 3초·30초·5분을 유지한다. 현재 코드에 `LIMITS_VERSION` 통합 설정이 없으므로 W49가 이를 구현할 때 `w48-v1`과 실제 임계값을 함께 기록해야 한다. 설정 누락을 임의의 버전으로 꾸미지 않는다.

## 2. 허용 조치와 원복

| 조치 | 허용 근거 | 금지·중단 조건 |
|---|---|---|
| `singleflight_enable` | 같은 v2 route key 중복 요청과 내부 병목이 확인되고, 장애 뒤 켜지는 독립 토글의 효과를 측정할 수 있을 때 | 기본 `_flights`는 이미 켜져 있다. 토글이 없는 현재 상태에서는 조치 후보와 복구 성과에서 제외한다. 유효 완료율 개선이 없거나 거절·시간 초과 증가 시 원복 |
| `bounded_queue_adjust` | 고유 요청 위주, 내부 큐 증가, 외부 지연 정상, 변경 전후 상한·대기 시간 확인 | 상한이 검증되지 않았거나 거절 증가·완료율 악화 시 실행 금지/원복 |
| `valid_cache_serve` | 동일 경로 조건, 유효 기한·통제 버전·검증 시각을 모두 만족하는 별도 조치 | 기본 메모리 캐시 적중은 복구 효과가 아니다. 만료·통제 변경·검증 실패 시 중단. 현재 독립 토글이 없으므로 성과에서 제외 |
| `fallback_provider_switch` | `route_upstream` 오류, 검증된 대체 공급원과 키·응답·한도 확인 | 내부 과부하만으로 전환 금지. 1차 회복 또는 2차 한도 80% 도달 시 중단. 카카오 결과 저장·캐시 금지 |
| `safe_degrade` | 유효 경로를 줄 수 없고 다른 허용 조치도 실패 | 경로 성공으로 집계 금지. 축제 검색·상세는 유지하고 사용자에게 경로 불가 표시 |
| `rollback` | 조치 후 유효 완료율 악화, 거절·시간 초과 증가, 권한·한도·유효성 위반 | 사건 ID, 이전 설정, 원복 시각·결과 기록 |

정책 코드는 허용 목록 밖의 제안과 근거 없는 제안을 거부한다. A1의 모델 시간 초과·형식 오류·금지 제안은 **같은 사건의 남은 시간과 시도 예산**으로 B1 규칙에 넘기고 실제 수행자를 `rule`로 기록한다. 이 전환을 A1의 순수 효과로 세지 않는다. W50 구현 전에는 이 표가 실행을 증명하지 않는다.

## 3. 고정 비교 프로토콜

| 항목 | v1 계약 |
|---|---|
| 비교군 | B0=감지·기록만, B1=고정 규칙 선택, A1=Agent 제안 후 같은 정책 게이트. 기존 `_flights`·메모리 캐시는 세 군에 동일하게 유지 |
| 시나리오 | 반복/고유 route key × burst/지속 × cold/warm의 8개 조건. 각 조건은 정상→내부 지연 주입→조치/관찰 순서. 외부 API에 부하를 보내지 않고 시험용 공급원을 사용 |
| 반복·순서 | 조건마다 seed `4801`, `4802`, `4803`으로 3회씩. 각 seed에서 B0→B1→A1, B1→A1→B0, A1→B0→B1 순서로 실행. 동일 seed의 세 군에 요청 본문·발행 시각·오류/지연 주입을 재생 |
| 부하 길이·표본 | 조건·군·seed마다 최소 **10분** 관찰, 장애 구간의 각 30초 창에 완료 표본 30개 이상을 목표로 offered 부하를 설정. 표본이 미달하면 결론 `inconclusive`로 표시하고 세 군에 동일한 더 긴 실행을 새 버전으로 재시험. 5분 복귀 확인을 완료할 관찰 시간을 확보 |
| 고정 자원 | 코드 커밋, 정책 버전, 작업자·CPU·DB·시험 공급원, 요청량·동시성·rate limit, 캐시 초기화 방식과 warm 데이터, 주입 시점·지연·오류를 기록하고 동일하게 유지. 시험 전 허용량은 세 군에서 동일하게 높여 자체 rate limit이 장애 원인이 되지 않게 함 |
| 완료 제한 | 요청 제출부터 **10초** 안에 검증된 경로를 받은 경우만 유효 완료. 제한 시간과 시각 기준을 세 군에서 동일하게 적용 |

W106 도구는 부하를 시작하기 전에 위 계약을 manifest로 저장하고, 사건 ID·seed·군·시나리오·코드 커밋·설정·원시 시계열 경로를 결과에 남긴다. 주입이 목표 장애를 만들지 못하거나 표본 조건을 못 맞추면 성능 우열을 주장하지 않는다. W96의 4~8건/조건 측정은 이 비교의 합격 자료가 아니다.

## 4. 지표와 판정

- `offered`는 발행한 전체 요청 수. 429/503·오류·시간 초과·시험 종료 시 미완료도 분모에 넣는다.
- `valid_completed_rate`는 10초 안에 검증된 경로를 받은 수 / `offered`. 202 접수, 경로 없는 200, 안전 축소, 늦은 완료는 분자에서 제외한다.
- API 응답 p95와 제출→유효 경로 완료 p95를 따로 계산한다. 성공 건의 지연만 표시할 때도 거절·오류·미완료 수를 나란히 표시한다.
- 중복률은 `1 - (고유 v2 route key 수 / offered)`이며 요청이 0건이면 미정이다. 단순히 목적지 이름이 같은 요청은 묶지 않는다.
- `recovery_rate`는 5분 지속 정상 복귀 사건 / **사전에 정한 유효 장애 사건**. 미복구·안전 축소·중단 사건도 분모에 남긴다.
- `MTTR`은 코드 감지 시각부터 5분 연속 정상 구간의 **끝 시각**까지다. 복구 사건의 평균·중앙값과 함께 미복구 건수·관찰 경과 시간을 별도로 공개한다.
- `final_mode`는 `normal_recovered`, `valid_cache`, `alternate_source`, `degraded`, `unresolved` 중 하나. 뒤 세 상태를 정상 복구율에 합치지 않는다.
- B1/A1이 B0보다 유효 완료율을 높이지 못하거나 거절·시간 초과를 늘리면 성공 판정하지 않는다. A1의 B1 대비 이득은 측정 결과로만 판단한다. 부하/사건 유효성, 원시 자료, 비용·AI 실패·전환 횟수를 함께 공개한다.

## 5. 위험 예측 계약

- 예측은 현재 시각까지의 offered RPS, 내부 p95, 큐/inflight, 거절·시간 초과만 사용한다. 미래 장애 판정이나 조치 결과는 입력에서 제외한다.
- 매 30초 유효 창 종료 시 **다음 2분 안에** 1절 장애 조건을 처음 만족할지 예측한다. 위험 점수 임계값은 평가 데이터와 분리한 학습/보정 구간에서 정하고 버전과 함께 잠근다. 평가 구간을 보고 임계값을 바꾸면 새 실험으로 취급한다.
- 최초 경보가 장애 감지보다 앞선 경우에만 사전 적중이다. 적중·오경보·누락·선행 시간을 사건 기준으로 보고한다. 유효 표본이 없는 구간은 예측 품질 분모에서 제외한 수를 별도 기재한다.

## 인계

- W44: 감지·조치·복귀의 상태와 정책 게이트, A1→B1 전환, 공유 예산을 설계에 반영.
- W49: 30초 창·최소 표본·원인별 시계열·버전·예측 입력을 구현. 감지와 예측의 차이를 기록.
- W50: 허용/거부/원복을 코드로 구현하고 기본 최적화와 장애 뒤 조치를 구별. 토글 없는 조치는 실험 성과에서 제외.
- W106/W51: 위 고정 입력을 재현하고 원시 결과로 효과를 판정. 목표 장애·표본을 만들지 못하면 결론 보류.
