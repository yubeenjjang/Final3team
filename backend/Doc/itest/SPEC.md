# 화면 흐름 통합 시험 명세

실제 FastAPI 라우터, JWT 인증, PostgreSQL 트랜잭션·RLS를 한 요청 흐름에서 다룬다. 화면과 동일하게 HTTP는 httpx ASGI 전송, 메시지는 ASGI WebSocket을 사용한다. 흐름별로 가입한 합성 계정 2~3명을 사용한다.

| 흐름 | 확인할 계약 |
| --- | --- |
| 인증 A32~A35 | 가입과 로그인 뒤 해시 저장을 확인한다. Refresh를 교체하고 이전 토큰 재사용 시 계정의 남은 Refresh도 폐기한다. 타인의 Refresh로 로그아웃할 수 없고 본인 로그아웃 후 보호 API는 401을 반환한다. |
| 축제·관심 A02·A03·A11~A13 | 승인·게시된 EV01만 목록·상세에서 보인다. 비공개 축제를 저장할 수 없고, 관심 저장·해제 뒤 목록과 본인 행 RLS가 일치한다. |
| 친구·채팅 A44~A47·A49·A50·A67·A71·A73 | 신청 당사자만 수락할 수 있다. 동시에 양쪽에서 요청하면 같은 1:1 방을 받는다. WebSocket으로 메시지를 보내고 마지막 수신 순번 이후의 내용을 HTTP로 재조회한다. 차단과 차단 해제 뒤에도 기존 방은 닫혀 있고 메시지를 조회할 수 없다. |
| 동행 A58~A64 | 글 작성, 신청, 승인 뒤 작성자와 승인된 신청자만 정확한 장소를 읽는다. 대기 중인 신청자는 API와 RLS 모두에서 차단된다. |
| 신고 A76·A77 | 해당 대화를 볼 수 있는 사용자가 메시지를 신고한다. 일반 사용자의 운영자 열람은 거절되고, 허용된 운영자 열람은 신고·방·열람자·사유를 DB에 기록한다. |
| 챗봇 A06·A06-1 | 질문 접수 202, PostgreSQL 큐 선점, 모의 답변 저장, 결과 조회를 연결한다. 타인 조회는 API와 RLS 모두에서 차단된다. |
| 정기 작업 DB 7-0·19절 | KST 06시 회차에 실행기를 한 번 호출한다. 30일 지난 거절 신청과 90일 지난 알림은 행을 지우고 최근 행은 보존한다. 성공 회차를 DB에서 확인한다. |

계약은 API 설계서의 해당 필드·오류 표와 DB 설계서의 001~026, 7-0 및 19절을 따른다. 시험에서만 인증·채팅 상태를 메모리에서 초기화하고 TourAPI 수집과 챗봇 답변을 합성 응답으로 대체한다.
