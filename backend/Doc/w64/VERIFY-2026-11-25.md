# W64 최신 yubeen 로컬 Docker 기동 검토

- 기준: `yubeen`의 2026-11-25 W64 점검. 별도 Compose 프로젝트 `codex-w64`, PostgreSQL 17+pgvector, Python 3.14 백엔드 이미지.
- 시험용 무작위 비밀번호만 임시 `.env`에 사용했다. 실제 공급원 키·실제 축제 데이터·운영 DB·AWS는 사용하지 않았다.
- 설정: `FESTIVAL_DATA=db`, `ROUTE_PROVIDER=real`, `ROUTE_STORE=db`, 시험용 `ROUTE_KEY_SECRET`. 외부 경로 요청은 보내지 않았다.

## 관측 결과

| 확인 | 결과 |
|---|---|
| 첫 기동 | DB `healthy` → migrate 001~028 적용(종료 0) → role-passwords 종료 0 → API `healthy` |
| HTTP | `GET /api/v1/health` 200, `status=ok`, `db=ok`; `GET /api/v1/festivals` 200, `is_mock=false`, `total=0`(빈 시험 DB) |
| 같은 설정으로 재실행 | migrate 001~028 모두 `건너뜀`, role-passwords 종료 0, API 계속 기동 |
| 포트·계정 | API는 `127.0.0.1:18064`만 노출, 컨테이너 사용자 `noldaga`; DB도 시험용 로컬 포트만 노출 |
| SEC-07 | 시험 비밀값 4개를 이미지 설정·빌드 히스토리·Compose 로그에서 대조: 일치 0건. 이미지에 `.env` 없음. API 컨테이너에 관리자 `POSTGRES_PASSWORD` 없음; 앱·서비스 계정 비밀번호는 런타임 설정으로 주입됨 |
| 정리 | 시험 컨테이너·네트워크·DB 볼륨과 임시 `.env` 삭제 |

## 판정과 범위

최신 `yubeen`의 **로컬 Docker 기동·DB 연결·재기동·비밀값 배제 검토는 통과**했다. 축제 목록 0건은 빈 시험 DB의 정상 결과이며 실제 축제 검색 성공 근거가 아니다. 실제 TourAPI 적재, TMAP 호출, 결과 A05 연속 조회와 AWS 적용은 각각 W100/W36·W56/W65의 별도 증거가 필요하다. Redis는 현재 `/health`에서 `not_configured`로 표시된다.
