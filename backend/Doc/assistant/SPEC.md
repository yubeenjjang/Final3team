# A06 챗봇 API 구현 명세

A06·A06-1·A06-2는 API 설계서 7-6과 9-1을 따릅니다. 기본값 `ASSISTANT_PROVIDER=mock`은 데모용으로 첫 조회에서 진행 중, 두 번째 조회에서 완료 또는 실패를 반환합니다. DB 모드는 202 접수 후 워커가 처리하며 A06-1 조회는 작업 상태를 변경하지 않습니다.

- 로그인 조회에는 기존 인증과 사용자 DB 세션을 사용합니다. 익명 작업 조회와 대화 이어가기는 각각 그 작업과 그 대화에서 발급한 10분짜리 `X-Run-Access-Token`으로 확인합니다.
- 같은 `request_id`로 다시 제출하면 권한 확인 뒤 동일 작업을 반환합니다. 익명 재제출은 처음 응답의 세션 쿠키 또는 그 작업의 조회 토큰이 필요합니다. 브라우저의 교차 출처 요청에서 쿠키를 쓰려면 허용된 출처에서 `credentials: "include"`를 지정합니다. 첫 응답의 쿠키와 토큰을 모두 받지 못한 익명 클라이언트는 새 요청 ID로 접수할 수 있습니다.
- SSE는 PostgreSQL 알림을 실시간으로 받고, 이미 종료된 작업에는 DB에서 확인한 종료 이벤트를 보냅니다. 구독 중 완료되면 조회 권한 확인 뒤 저장 답변을 `token` 한 조각으로 보냅니다. 진행 기록은 재생하지 않습니다.
- PostgreSQL 워커는 작업 ID와 시도 번호만 넘깁니다. 질문·답변은 연락처와 한국 주소 형식을 마스킹합니다. 경로 공급원 결과 본문은 챗봇 응답에 저장하지 않으며, 경로 ID가 있는 답변에는 고정 안내 문구를 씁니다.
- 연결된 Festival Agent가 없으면 기존 모의 축제 답변을 사용합니다. DB 모드에서 이미 조회 권한을 확인한 귀가 요청은 작업 결과에 연결할 수 있습니다. 새 귀가 질문은 귀가 화면으로 안내합니다.
- JWT로 실제 계정에 접근하려면 `AUTH_PROVIDER=db`를 함께 설정합니다. `ASSISTANT_TOKEN_SECRET`은 익명 조회 토큰 재발급과 본문 지문 비교에 사용하며 API 인스턴스 간에 값을 공유합니다.
