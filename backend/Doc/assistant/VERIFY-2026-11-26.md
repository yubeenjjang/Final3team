# A06 Compose 워커 통합 검증 — 2026-11-26

- 환경: Windows Docker Desktop Linux 엔진, 별도 Compose 프로젝트 `codex-a06-verify`, 일회용 PostgreSQL 17+pgvector DB.
- API·워커 모두 `ASSISTANT_PROVIDER=db`, 같은 시험용 `ASSISTANT_TOKEN_SECRET` 사용. 실제 공급원 키와 운영 DB는 사용하지 않았다.
- `infra/deployment/compose.yaml`의 `assistant` 프로필로 DB → 001~028 마이그레이션 → 역할 비밀번호 설정 → API와 `assistant-worker`를 실행했다. 시험 포트는 호스트의 127.0.0.1에만 열었다.

## 발견·수정

첫 기동에서 API `/api/v1/health`는 `db=ok`였지만 워커에 `assistant worker queue unavailable` 경고가 반복됐다. `PostgresAssistantQueue.claim()`의 내부 오류를 확인한 결과, 공통 `DBSettings` 로더가 서비스 연결에도 `DB_USER_USERNAME`·`DB_USER_PASSWORD`를 요구하는데 워커 Compose 환경에 두 변수가 없었다. 워커 환경에 추가하고 재기동한 뒤 경고가 멈췄다.

## 확인 결과

| 확인 | 결과 |
| --- | --- |
| API·DB·워커 기동 | API와 DB healthy, 워커 running |
| API DB 헬스 | `/api/v1/health` 200, `db=ok`, `redis=not_configured` |
| 성공 요청 | A06 `POST /assistant/query` → 202 `queued`; A06-1 조회 → `succeeded`, 답변 있음 |
| DB 실행 기록 | 성공 실행 `attempt=1`, `started_at`·`ended_at` 기록됨 |
| 실패 요청 | 모의 실행기에서 실패 문구 접수 → 202 `queued`; 조회 → `failed`, `AI_AGENT_FAILED`, `ended_at` 기록됨 |
| 워커 로그 | 설정 수정 뒤 DB 큐 오류 경고 없음 |

이 시험의 답변은 **모의 Festival 실행기**에서 생성됐다. 실제 Festival Agent 연결과 5개 에이전트 협업, Redis/Celery 전환, 운영 AWS 실행은 이 결과로 검증되지 않는다. 귀가 경로 A04·A05는 이 시험에서 변경하지 않았다.
