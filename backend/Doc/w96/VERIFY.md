# W96 귀가 API 내부 계측 중간본 — 2026-11-25

## 실행 조건

- 기준: `yubeen` 5581089 이후 작업 트리, Python 3.14 Linux Docker, 최신 A04 `/api/v1/routes/return`와 A05 조회.
- 실제 FastAPI 라우터·요청 제한·`RealRouteService`·중복 실행 및 메모리 캐시 경로를 사용했다. 외부 TMAP·카카오 대신 고정 50ms 지연의 시험용 공급원을 주입했다. DB 저장과 외부 네트워크는 포함하지 않았다.
- 반복/고유 목적지 × burst/지속 × cold/warm 8조건, 조건당 8요청·동시성 4·지속 간격 100ms, 총 64요청. 같은 서비스의 cold 실행 다음에 warm 실행을 연속 측정했다. 요청 제한은 내부 계측을 위해 분당 10000으로 고정했다.
- 원본 수치: [RESULT-2026-11-25.json](RESULT-2026-11-25.json). 계측 도구: `backend/tests/w96_internal_probe.py`.

## 일회용 DB 경로 확인

- Linux Docker의 일회용 PostgreSQL 17 + pgvector에 001~028을 적용하고 앱·서비스 계정을 분리했다. `ROUTE_PROVIDER=real`, `ROUTE_STORE=db`, `FESTIVAL_DATA=db`로 공개 시험 축제 한 건을 사용했다. 외부 공급원은 고정 결과를 돌려주는 시험용 공급원으로 대체했다.
- 최신 A04/A05를 동시에 4요청씩 호출한 결과, 반복 목적지 4/4 유효 완료·공급원 실행 1회·최대 완료 278.36ms, 고유 목적지 4/4 유효 완료·공급원 실행 4회·최대 완료 191.02ms였다. 시험 `backend/tests/routes/test_w96_db_probe.py` 통과. DB와 시험 네트워크는 검증 후 삭제했다.
- 이 수치는 한 번 실행한 4건 표본의 최대값이며 DB 운영 지연 목표나 실제 공급원 지연을 뜻하지 않는다.

## W48 인계 및 남은 검증

- 반복 목적지의 실행 묶기를 복구 후보로 제시할 수 있다. W48은 이 결과를 사전 계측으로 사용하고, 동일 부하 B0/B1/A1 비교 전에 목표 지연·완료율·관측창·반복 수·캐시 초기 조건을 고정한다.
- W48은 반복 목적지의 실행 묶기를 복구 후보로 검토하고, 정식 비교 전 동일 입력·캐시 초기 상태·자원 조건을 고정한다. 실제 공급원에는 부하를 주입하지 않는다. 외부 공급원 지연은 별도 소수 실호출로만 확인한다.
