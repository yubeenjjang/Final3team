# A24 구현 계획

1. 018 이후 `019_admin-review.sql`로 사유 제약을 넓히고 보류 중인 TourAPI 데이터를 이관합니다. 수집에서 새로운 품질·누락 사유가 생기면 같은 미처리 사유가 있는지 확인하고 대기열에 한 건을 저장합니다.
2. 기존 인증과 역할 검사에 라우터를 연결합니다. 실제 저장소는 서비스 계정 세션을, 모의 저장소는 같은 인터페이스의 메모리를 사용합니다.
3. POST는 수집기와 같은 축제 행부터 잠그고 대기열 행을 잠급니다. 상태와 게시 조건을 확인하고 축제·대기열·이력을 함께 기록합니다.
4. 모의 HTTP 시험에서 역할, 필터, 페이지, 게시 조건, 결정과 동시 요청을 확인합니다. 019까지 적용한 일회용 PostgreSQL에서 `TEST_DB_URL`을 설정하면 DB 표시 시험에 RLS·서비스 역할·동시 결정이 포함됩니다. `Docs/Step 2/db/run_tests.sh`는 019 적용·되돌리기·재적용을 확인합니다.
