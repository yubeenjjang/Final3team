# 친구 API A43~A50

[API 설계서 6-4-3](../../../Docs/Step%202/API_설계문서.md)과 [DB 설계서 6-6·7-0·19절](../../../Docs/Step%202/DB_스키마_설계서.md)을 따릅니다.

| API | 동작 |
|---|---|
| A43 | 닉네임 2~12자를 대소문자 구분 없이 정확히 검색합니다. 본인·비활성 계정·양방향 차단 관계는 빠집니다. 사용자당 최근 60초에 20회까지 허용하며 초과 시 429와 `Retry-After`를 반환합니다. |
| A44 | 신청을 만들고 201을 반환합니다. 교차 신청은 기존 ID로 수락 처리하며 201과 `accepted`를 반환합니다. 본인·없는 사용자·비활성 사용자는 404입니다. 같은 방향의 대기 신청, 친구 관계, 차단 관계는 설계서의 409 코드로 응답합니다. |
| A45 | 기본은 받은 신청이며 `box=sent`로 보낸 신청을 조회합니다. 응답 후 30일이 지난 거절·취소 신청은 제외합니다. |
| A46 | 받은 사람은 수락·거절, 보낸 사람은 취소할 수 있습니다. 다른 사용자에게 속한 신청은 404, 당사자에게 허용되지 않은 동작은 403, 이미 처리된 신청은 409입니다. |
| A47 | 친구가 된 시각 내림차순과 상대 UUID 순으로 정렬해 1페이지부터 20명씩 돌려줍니다. |
| A48 | 해당 친구 관계를 삭제하고 204를 반환합니다. |
| A49 | 차단을 등록하며 한 트랜잭션에서 친구 관계를 지우고 대기 신청을 취소하고 기존 1:1 방을 닫습니다. 자기 자신은 422입니다. 없는 계정 ID에 대해서는 200을 반환하며 새 행을 만들지 않습니다. |
| A50 | 본인이 만든 차단 행을 삭제하고 204를 반환합니다. 삭제를 확정한 뒤에만 `notify_chat_unblocked(blocker_id, blocked_id)`를 호출합니다. 기존 1:1 방은 닫힌 채 유지되고 A67에서 새 방을 개설합니다. |

- 인증은 기존 JWT와 사용자 세션을 사용하며 DB 조회에는 005의 RLS가 적용됩니다. A43은 009의 `app_find_user_by_nickname`을 호출합니다.
- DB 쓰기는 기존 서비스 역할을 사용합니다. 트랜잭션은 사용자 행을 UUID 오름차순으로 잠그고 현재 상태를 검사합니다. A46은 이 잠금을 얻은 뒤 권한과 상태를 다시 확인합니다. A67 연동 시 같은 잠금과 친구·차단 검사를 방 생성 트랜잭션에서 사용합니다.
- 기본 mock 모드는 기존 가입·로그인·탈퇴와 친구 상태를 메모리에서 공유합니다. A43 제한은 `FriendSearchLimiter` 인터페이스를 사용합니다.
- 30일이 지난 거절·취소 신청의 물리 삭제는 `api.jobs.purge_friend_requests`가 처리합니다. 대기와 수락 신청은 정리 대상에서 제외합니다.
