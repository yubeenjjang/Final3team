# db2b 구현 명세

## 공개 조회

A02·A03, A07 공지, A26 주변 정류장·역 DB 조회는 공통 비동기 `user_db_session(user_id=None)`에서 앱 계정 권한과 RLS를 적용합니다. A02는 첫 SQL 전에 연결에 `REPEATABLE READ`를 설정하고 같은 트랜잭션에서 전체 건수와 페이지를 읽습니다. 격리 수준은 연결 반납 시 초기화됩니다. A03은 010에서 허용한 원본 번호를 기존 방식대로 읽습니다.

`FESTIVAL_DATA=mock`이 기본입니다. 공개 조건, 응답 필드, 누락 ID의 404와 기존 모의 시나리오를 유지합니다. DB에 연결된 로그인 경로는 기존 인증 의존성이 검증한 사용자 ID를 사용합니다.

A01은 기존 DB 모드 조건에서 공통 앱 세션으로 `SELECT 1`을 실행합니다. 전체 확인에 1초 제한을 적용하고 같은 트랜잭션에 쿼리 제한을 설정합니다. DB 설정·접속·쿼리 오류에는 기존 503 상태 응답을 반환합니다.

## 수집과 스냅샷

TourAPI 수집 CLI는 공통 서비스 세션에서 기존 수집 잠금을 잡습니다. 스케줄러와 CLI 모두 잠금이 유지되는 동안 같은 서비스 풀의 다른 연결에서 작업 시작과 적재 결과를 각각 커밋합니다. 관광공사 스냅샷은 서비스 세션으로 읽고, 저장할 때는 기존 대상별 잠금과 동일 날짜 중복 차단을 유지합니다. 서비스 연결 반납은 공통 풀의 `RESET ALL`을 따릅니다.

기존 001~028의 권한·RLS와 스냅샷 보존 기준을 적용합니다. 실 DB 실행에는 공통 설정이 요구하는 앱·서비스 DB 접속 환경변수가 필요합니다.
