# 알림·신고·관리자 열람 명세

API 6-4-6·9-1 ⑧과 DB 6-8·7-0·7-2·19절을 따릅니다. 기본 모드는 mock이며 `AUTH_PROVIDER=db`에서 JWT의 `sub`로 앱 역할의 RLS 세션을 엽니다.

- A74·A75는 본인 알림만 조회하고 `read_at`만 갱신합니다. 최신순으로 페이지당 20개를 반환하고 읽지 않은 수는 전체 보존 범위로 계산합니다. 90일이 지난 알림은 화면과 WebSocket에서 제외하며 기존 정리 작업이 행을 삭제합니다.
- 동행 신청은 글 작성자, 동행 승인·거절은 신청자, 친구 신청은 받는 사람, 친구 수락은 처음 보낸 사람, 친구 단체방 초대는 초대받은 사람에게 알립니다. DB에서는 상태 변경과 알림이 같은 트랜잭션에 들어갑니다.
- A76의 신고 사유는 `spam`·`abuse`·`harassment`·`fraud`·`privacy`·`other`입니다. 신고 대상은 동행 글·메시지·방·활성 사용자입니다. 방 신고는 현재 입장한 멤버, 메시지 신고는 RLS로 그 메시지를 읽을 수 있는 사용자만 접수합니다. 동일 신고자와 대상 유형·ID 조합은 KST 날짜당 한 건입니다.
- A77은 `operator`·`admin`의 현재 프로필 역할을 확인한 뒤 서비스 계정을 사용합니다. 목록 요약, 단건 상세, 조치 결과의 필드는 API 6-4-6의 표를 사용합니다. 상세를 처음 열면 `reviewing`으로 전환합니다. 바로 처리하면 같은 트랜잭션에서 `reviewing`을 거쳐 `actioned` 또는 `dismissed`로 전환합니다.
- 채팅 상세는 `chat_admin_access`에 관리자·방·신고·신고 사유를 먼저 기록한 뒤, 방 정보와 필요한 메시지 한 건을 읽습니다. 방 신고의 `message`는 null입니다. 보존 기한이 지난 메시지는 해당 행의 메타데이터와 null 본문을 반환합니다.
- 메시지 숨김은 `deleted_at`, 글 숨김은 `hidden_at`·`hidden_by`, 방 닫기는 `read_only`, 사용자 차단은 계정 `disabled`를 적용합니다. 조치와 처리 메모를 같은 트랜잭션에서 저장합니다.
