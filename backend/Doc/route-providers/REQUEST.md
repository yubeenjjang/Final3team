# 요청서 — 귀가 경로 실제 조회 (TMAP 1차 · 카카오 2차) (2026-11-23, 권오현)

## 왜 만드나
- 12/8 중간 발표 흐름의 뒤 절반 "AI 안심 귀가 → 목적지 입력 → **경로 결과 또는 조회 불가 안내**"를 실제 공급원으로 보여 주려고(신유빈 11/23 요청 ②③). 파일 담당: `providers/tmap.py`·`kakao.py`·`routers/routes/` = 권오현(협업 규칙).
- 강사 11/20 API 피드백 2: 공급원별 저장·캐시 규칙을 **실제 처리 코드**와 맞추고, 동기 응답에서만 줄 수 있는 결과(카카오)와 비동기 상태 조회를 구분.

## 요청의 말
1. 축제 장소(또는 사용자가 고른 출발지)에서 목적지까지 **대중교통 경로**를 TMAP(1차)으로 받고, 실패하면 **카카오(2차)로 한 번** 받는다(API 설계문서 5절·10-3).
2. 목적지 글자(예: "서울역")를 좌표로 바꾼다(카카오 장소 검색). 검색 결과는 저장하지 않는다.
3. 원본을 **지금 모의 응답과 같은 모양**(`route_candidates`, `[위도, 경도]` 경로선 등)으로 바꾼다. 화면·에이전트는 바꿀 것이 없어야 한다.
4. **한도 보호:** TMAP 하루 10건(오류 응답도 셈), 카카오 하루 1,000건. 공급원별로 세고 다 쓰면 그 공급원은 부르지 않는다. 둘 다 못 쓰면 `ROUTE_QUOTA_EXCEEDED`.
5. **저장 규칙:** TMAP 결과는 60초 캐시 가능(24시간 넘게 보관 금지), **카카오 결과는 저장·캐시 금지** — 접수 응답(동기)에서만 주고, 나중 조회(A05)로는 `ROUTE_SECONDARY_SYNC_ONLY`.
6. 같은 조건 요청이 동시에 오면 한 번만 부른다(요청 병합).
7. 기본은 **모의**. 환경변수로 켤 때만 실제 공급원을 부른다(개발·시험·여러 사람 시연에서 한도 보호).
8. 시험은 네트워크 없이. 실제 응답 원본은 저장소에 넣지 않는다(태경 님 **합성 고정 파일** 사용).
9. 키는 환경변수로만. 코드·로그·시험·문서에 남기지 않는다.

## 결정 대기 (이번 작업은 진행, 결과만 적어 둠)
- **TMAP 유료 전환(`TMAP_PAID_PLAN`, 11/26 결정 예정):** 지금은 하루 10건. 12/8 리허설까지 생각하면 부족할 수 있음 → 한도 숫자는 환경변수로 둔다.
