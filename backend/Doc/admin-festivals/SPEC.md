# A55·A56 관리자 축제 직접 등록·수정·게시

API 설계서 6-6 및 오류표, DB 설계서 6-3·7-0·7-1·19절과 018·019를 적용한다. FastAPI의 공통 인증에서 JWT의 `sub`로 RLS 세션을 열어 본인 프로필 역할을 조회한다. `admin`만 실제 변경을 할 수 있고, 검증 뒤 `noldaga_service`로 축제·출처·검토 대기열·감사 이력을 다룬다. 기본은 모의 인증 및 메모리 저장이다. 모의 관리자는 서버에 32바이트 이상의 `MOCK_ADMIN_FESTIVALS_TOKEN`을 설정하고 Bearer로 전달할 때 활성화된다. 모의 A24·A55·A56과 공개 축제 목록·상세는 동일 프로세스의 상태를 공유한다.

- A55는 필수 이름·장소·지역·시작일·종료일·위경도 및 작업 사유를 받고, `category='festival'`, `source_class_level2='EV01'`, `review_status='pending'`으로 저장한다. `festival_sources`에 `source_id='admin_manual'`, `source_item_id=festival_id`를 연결한다. 게시 후 A02·A03은 `source='admin'`으로 표시한다.
- 이름과 장소의 앞뒤 공백을 제외한 글자와 시작일·종료일이 동일한 등록은 기존 축제에 `duplicate` 검토 항목을 추가하고, 커밋 후 `409 DUPLICATE_FESTIVAL`을 반환한다. 동일한 제안이 처리 대기 중이면 기존 대기열 항목을 사용한다. 승인 전에는 원래 축제의 값이 유지된다.
- A56은 전달된 칸을 잠긴 축제 행과 합쳐 검증한다. 주소는 선택이며, 값이 있으면 한 줄의 비어 있지 않은 문자열이어야 하고 유효한 위경도가 한 쌍 있어야 한다. 기존 주소 없는 축제는 좌표 둘 다 NULL일 수 있다. 날짜를 함께 저장할 때 시작일은 종료일 이하여야 한다. 위도는 33~39, 경도는 124~132, 최대 소수점 여섯 자리다. 이미지·홈페이지 주소는 HTTP(S)이며, 대표 이미지가 있으면 최종 값에 저작권 유형(Type1/Type3)이 필요하다. 저작권 객체의 출처 문구와 수정 허용 여부는 공개 시 출처와 유형으로 표시한다.
- `published=true`는 승인·게시하고 게시 시각이 비어 있을 때 현재 시각을 넣는다. `published=false`는 숨기고 DB의 최초 게시 시각과 연결 정보를 보존한다. A56의 비공개 응답에는 게시 시각을 null로 표시한다. 재게시에는 보존한 시각을 반환한다. 게시 여부가 생략되면 내용만 수정한다.
- 실제로 달라진 컬럼마다 이전 값·새 값·사유·작업자 UUID·작업 시각을 한 트랜잭션에서 보관한다. 동일한 값을 재전송하면 추가 수정 이력이 생기지 않는다. 중복 검토 항목의 신규 생성도 감사 이력에 연결한다. 이력 보존은 DB 7-0의 서비스 기간을 따른다.

## 공급원 재수집

TourAPI 정기 수집과 증빙 스냅샷은 잠긴 축제 행의 관리자 컬럼별 감사 이력을 확인한다. 수집 값이 다르면 수정 칸을 보존하고 내부 컬럼명을 사용한 제안을 A24 `conflict`로 전달한다. 같은 축제의 미처리 충돌에는 새 제안을 병합한다. 주소·좌표·좌표 출처 및 대표 이미지·썸네일·저작권 유형은 각각 연관된 값으로 보호한다. 날짜는 개별로 보호하되, 한쪽만 반영해 기간이 역전되면 변경하려던 두 날짜를 함께 보류한다. 미수정 칸의 수집값과 동기화 정보는 기존 수집 경로를 따른다. 비축제·미분류 전환과 공급원 누락은 기존 보류 규칙을 적용한다.
