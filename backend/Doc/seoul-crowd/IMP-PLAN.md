# IMP-PLAN — W89 서울 축제 주변 지역 혼잡 연결

## 1단계 — 조사

- 서울시 공식 121개 코드·경계와 이용 조건을 확인했습니다.
- 서울시 API를 5회 호출해 키 없는 고정 파일 3개를 준비했습니다.
- 학원 노트북 A02/A03의 공개 서울 축제 188건을 확인하고 터널을 종료했습니다.
- [연결표](mapping_draft.md)와 [JSON 초안](../../api/data/seoul_crowd_mapping.json)을 조사 참고 자료로 보존합니다.

## 2단계 — A10 구현

1. `find_festival`로 공개 축제를 조회한 뒤 `seoul_areas.json` 경계를 기준으로 1km 이내 가까운 세 구역을 찾습니다. 구역 내부는 0m입니다.
2. `api/providers/seoul_citydata.py`에서 구역 코드로 조회하고 제한 시간·HTTP·본문 코드·구역 코드·필수값을 검사합니다.
3. `api/services/seoul_crowd.py`에서 응답과 안내 문구를 작성합니다. 구역별 60초 캐시, 동시 요청 병합, KST 일일 예산을 적용합니다.
4. 라우터와 `main.py`에서 `CROWD_PROVIDER=mock|real`을 적용합니다. 실제 모드만 `is_mock:false`이며 `X-Mock`이 없습니다.
5. 아래 항목을 고정 파일과 가짜 전송으로 검증하고 [API 설계문서](../../../Docs/Step%202/API_설계문서.md)와 연동 현황표를 갱신합니다.

### 완료 체크리스트

- 0m·1km 경계·범위 밖, 거리순 최대 3곳, 서울 밖·좌표 없음·주변 구역 없음의 사유 확인
- 관측·대체·오래된 자료의 구역명·거리·기준 시각·안내와 부분·전체 실패 확인
- 공급원 HTTP·본문 오류, 다른 코드, 형식 오류, 제한 시간, 일일 예산 소진과 KST 날짜 변경 확인
- 구역 캐시 만료, 동시 요청 병합, 정상 모의와 `source_error`·`stale` 시나리오 확인
- 실제 A10의 헤더, 기존 응답 키 및 Festival Agent 분기 유지 확인
- `backend/`에서 전체 `python -m pytest` 실행
