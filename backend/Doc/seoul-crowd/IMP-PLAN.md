# IMP-PLAN — W89 서울 축제 주변 지역 혼잡 연결

## 1단계 — 조사

- 서울시 공식 121개 코드·경계와 이용 조건을 확인했습니다.
- 서울시 API를 5회 호출해 키 없는 고정 파일 3개를 준비했습니다.
- 학원 노트북 A02/A03의 공개 서울 축제 188건을 확인하고 터널을 종료했습니다.
- [연결표](mapping_draft.md)와 [JSON 초안](../../api/data/seoul_crowd_mapping.json)을 조사 참고 자료로 보존합니다.

## 2단계 — A10 구현

1. [SPEC](SPEC.md#2026-11-242027-01-31-시연-후보)에 기간이 겹치는 확정 후보 세 곳과 시연 순위를 기록합니다.
2. `api/services/seoul_crowd_mapping.py`에서 승인 자료를 읽습니다. `find_festival`의 장소와 맞는 승인 코드만 공식 카탈로그에서 골라, 기존 1km 거리 계산으로 가까운 세 구역까지 연결합니다.
3. 서울시 어댑터의 HTTP·본문·기준 시각 검증, 3초 제한, KST 하루 예산을 재사용합니다. `api/services/seoul_crowd.py`는 대체 자료를 캐시와 공개 응답에서 제외하고 주변 지역 혼잡을 안내합니다.
4. 기존 `CROWD_PROVIDER` 모드, A10 헤더와 응답 키, 내장 모의 자료를 유지합니다. 모의 구역에도 주변 지역 혼잡 문구를 추가합니다.
5. 저장된 고정 파일과 가짜 전송으로 검증하고 [API 설계문서](../../../Docs/Step%202/API_설계문서.md)의 A10 및 연동 현황표를 갱신합니다.

### 완료 체크리스트

- 0m·1km 경계·범위 밖, 승인 구역만 거리순 최대 3곳, 서울 밖·좌표 없음·승인 없음·반경 내 승인 구역 없음의 사유 확인
- 승인 전 실제 요청과 장소 변경 후 요청이 공급원·호출 예산에 닿지 않는지 확인
- 관측·오래된 자료의 구역명·거리·기준 시각·출처, 대체 자료의 응답·캐시 제외, 부분·전체 실패 확인
- 공급원 HTTP·본문 오류, 다른 코드, 형식 오류, 제한 시간, 일일 예산 소진과 KST 날짜 변경 확인
- 구역 캐시 만료, 동시 요청 병합, 정상 모의와 `source_error`·`stale` 시나리오 확인
- 실제 A10의 헤더, 기존 응답 키 및 Festival Agent 분기 유지 확인
- 저장소 루트에서 `codex/_COMMON.md`의 공통 명령으로 전체 실행
