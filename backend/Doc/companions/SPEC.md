# 동행 API 계약

기준은 API 설계서 6-4-4 및 공통 오류표, DB 설계서 3절·6-8절·7-0절·19절이다. 이 버전의 동행 API는 A57~A65이다.

| API | 경로 (앞에 `/api/v1`) | 결과 |
|---|---|---|
| A57 | `GET /festivals/{festival_id}/companion-posts` | 공개 목록, 기본 `open`, 페이지당 20개 |
| A58 | `POST /companion-posts` | 201, 글 ID와 방 ID |
| A59 | `GET /companion-posts/{post_id}` | 공개 상세와 로그인한 사람 본인의 신청 상태(작성자와 입장한 승인 참여자에게만 실제 `room_id` 포함, 그 외 `null`) |
| A58 보완 | `PATCH /companion-posts/{post_id}` | 작성자가 일정·정원·조건·메모를 수정, 글 ID와 상태 |
| A60·A61 | `POST / GET /companion-posts/{post_id}/applications` | 신청 201 또는 작성자용 대기·승인 목록 |
| A62 | `POST /companion-applications/{application_id}/{action}` | 작성자의 승인·거절 또는 신청자의 대기 신청 취소 |
| A63·A64 | `PUT / GET /companion-posts/{post_id}/meeting-place` | 작성자만 등록·수정, 작성자와 입장한 승인 참여자만 조회 |
| A65 | `POST /companion-posts/{post_id}/{action}` | 작성자의 `close`(모집 마감)·`end`(동행 종료)·`cancel`(만남 전 취소) |

- 만남 시각은 오프셋이 있는 미래 시각으로 받으며 축제 시작일·종료일을 한국 날짜로 비교한다. 모집 인원 1~10명은 작성자를 제외한다.
- 대기·승인·거절 신청이 있으면 재신청할 수 없다. 대기 신청을 취소하면 재신청할 수 있다. 대기 중인 신청자의 방·정확한 장소 접근 권한은 승인 트랜잭션이 커밋될 때 생긴다.
- 수동 마감과 정원 충족은 공개 응답에서 `full`이다. 정원을 늘리면 정원 충족으로 닫힌 모집에 다시 신청할 수 있다. 수동 마감은 정원 수정이나 탈퇴에 따른 정원 반환 뒤에도 유지된다.
- 게시할 때 작성자만 입장한 동행방을 만들고, 승인할 때 참여자 입장과 시스템 메시지를 저장한다. 신청·승인·거절과 장소 변경·동행 종료·취소 알림은 상태 변경과 함께 저장한다.
- 종료·취소된 방은 읽기 전용이다. 만남 이후 `COMPANION_AUTO_END_H`(기본 12시간)가 지나면 종료한다. 종료·취소 72시간 뒤 장소 행을 삭제하고 모집 메모·신청 메시지·채팅 본문을 비운다. 모집·신청 상태와 방·채팅 순번은 이력으로 남긴다.
