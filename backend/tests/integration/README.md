# 통합 시험 (R04)

기능별 시험(`tests/api/`)은 API 하나씩 확인한다. 여기서는 **사용자 흐름 순서대로 여러 API를 이어서** 확인한다.
모의 서버(`api.main:app`)만 쓰며 외부 API는 부르지 않는다. 실패 상황은 `X-Mock-Scenario` 헤더로 재현한다.

## 실행

`backend/` 폴더에서:

```bash
uv run --with-requirements api/requirements.txt pytest tests/integration -q
```

## 흐름 목록

| 번호 | 흐름 | 확인하는 것 |
|---|---|---|
| I01 | 축제 검색 → 상세 → 공지·날씨·혼잡 → 귀갓길 접수 → 조회 | 모든 단계가 같은 축제·지역으로 답함, 경로 좌표가 `[위도, 경도]`, 교통통제 미확인 안내 |
| I02 | 요청 추적 번호 | 화면이 보낸 `X-Request-ID`가 접수·조회 응답에 그대로 돌아옴 |
| I03 | 경로 공급원 장애·시간 초과 → 재시도 | `unavailable`·`timed_out` + 재시도 가능 표시, 같은 번호로 다시 보내면 실패한 요청을 돌려받음, 새 번호로 재시도하면 성공 |
| I04 | 서버 과부하 → 재시도 | 503 `ROUTE_OVERLOADED`(재시도 가능) 뒤 새 요청은 접수됨 |
| I05 | 버튼 두 번 누름 | 요청은 하나만 생기고 조회 진행이 이어짐, 같은 번호에 다른 내용은 409 |
| I06 | 좌표 없는 축제 | 축제 기준 경로 400, 날씨·혼잡 `unavailable`, 공지는 정상, 장소끼리 경로는 가능 |
| I07 | 가는 길 → 귀갓길 | 방향이 섞이지 않음, 서로의 주소·토큰으로 조회 불가 |
| I08 | 가입·로그인 → 관심 저장 → 관심 축제로 귀갓길 → 로그아웃 | 로그아웃 뒤 관심 목록 401 |
| I09 | 두 사용자 관심 축제 | 서로 섞이지 않고, 한 사람이 지워도 다른 사람 것은 남음 |
| I10 | 토큰 갱신 → 옛 토큰 재사용 | 재사용 감지 시 새 토큰까지 폐기 |
| I11 | 챗봇 귀가 질문 → 챗봇이 준 경로 번호·토큰으로 귀가 조회 | 질문한 축제로 경로가 만들어짐, 같은 대화 번호로 이어 질문 |
| I12 | 챗봇 실패 | 실패 안내가 나오고 축제 검색·귀갓길은 그대로 동작 |
