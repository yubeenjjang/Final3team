# Codex 작업 지시서 — 6단계 검토 수정 (REVIEW_1122_codex.md 반영)

규칙은 `frontend/Doc/codex/_COMMON.md`. 기준 문서는 `frontend/Doc/REVIEW_1122_codex.md`의 '꼭 고칠 것' 표. **`frontend/src/`, `frontend/e2e/`, `frontend/tailwind.config.ts` 안에서만** 고친다(새 패키지 금지).

고칠 것(번호는 REVIEW 표 번호):
1. 보안 — AI 답변 → 귀가 결과로 넘길 때 `token`을 URL 쿼리에 넣지 않는다. `sessionStorage`(탭 안)로 넘기고, 기존 `?id=&token=` 직접 열기는 읽자마자 `history.replaceState`로 주소에서 지운다.
2. 보안 — 로그인·회원가입 폼에 `method="post"`를 명시하고, 화면 스크립트가 준비되기 전(하이드레이션 전)에는 제출 버튼을 비활성화한다.
3·4. 토큰 갱신 — 로그인·로그아웃마다 세션 번호를 바꾸고, 갱신 결과는 시작 때 세션과 같을 때만 반영. 이미 다른 요청이 토큰을 갱신했으면(요청에 쓴 토큰 ≠ 현재 토큰) 갱신 없이 새 토큰으로 1번만 재시도, 진행 중인 갱신은 공유.
5. 축제 목록 — 필터 변경·화면 이탈 시 '더 보기' 요청도 취소, 요청 당시 필터가 현재 필터일 때만 반영.
6·7. 찜 — 초기 찜 상태 확인 중에는 로그인 사용자의 하트를 잠그고, 변경 뒤 도착한 이전 조회는 버림. 상세도 홈과 같은 페이지 순회로 찜 여부 확인.
8. 요청 제한 시간 — 귀가 접수·조회, AI 접수·조회 요청 각각에 제한 시간(10초)을 두고, 넘으면 취소 후 기존 실패·재시도 화면.
9. 직접 열기 결과 화면의 '다시 시도' — 조회 한도 초과는 같은 경로 다시 조회, `timed_out`·`unavailable`은 원래 입력이 있으면 새 `request_id`로 재접수, 입력이 없으면 '새 경로 찾기'로 입력 폼을 보여 줌.
10. 카카오 SDK 초기화 실패 시 스크립트·캐시 정리, `maps.load` 콜백에 제한 시간, 실패는 대체 화면.
11. 접근성 — 혼잡 배지 글자와 '정보가 오래됐어요' 문구가 배경 대비 4.5:1 이상이 되게 토큰 조합 변경(색은 토큰만).
12. 이메일 검사에 `_` 등 서버가 허용하는 문자 허용(서버 규칙: `^[^@\s]+@[^@\s]+\.[^@\s]+$`과 같게), `sample_user@example.com` 통과 시험 추가.
13. D-day의 '오늘'을 `Asia/Seoul` 기준 공통 함수로 구하고, 서울 자정 경계 시험(UTC 환경에서도 같은 결과) 추가.
14. (수정 없음) 로그인·회원가입의 탭 숨김은 SPEC F3 예외로 확정됨 — 그대로 둔다.
15. 헤더 닉네임 첫 글자는 `Intl.Segmenter`로.
16. 글꼴 이름을 `Pretendard Variable`로 CSS·Tailwind 첫 글꼴 통일.
+ 고치면 좋은 것 — 실패 카드에서 오류 문구와 `notices`가 같으면 한 번만 표시.

각 항목에 단위 시험을 추가(가능한 것). 기존 e2e(`e2e/flows.spec.ts`)는 바뀐 동작(토큰을 URL로 넘기지 않음)에 맞게만 고친다.
끝내는 조건: `npm run typecheck && npm run lint && npm test`가 통과하면 멈춘다(빌드·e2e는 Claude가 실행). commit하지 않는다.
