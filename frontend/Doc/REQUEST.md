# 요청서 — 웹 화면 1차 (대표 흐름) (2026-11-22, 권오현)

> 최신 범위는 `FRONTEND-PLAN.md`, 디자인은 `UI-DESIGN-SYSTEM.md`, API는 `API-INTEGRATION.md`를 우선한다.

## 왜 만드나
- 백엔드 모의 API(`backend/api/`, `backend/Doc/`)가 생겼고, 이수언 님 UI 시안(Figma, 11/20)이 나왔다. 이 둘을 이어 **실제로 눌러 볼 수 있는 웹 화면**을 만든다.
- 프론트 폴더는 팀 규칙상 정예진·이수언 님 담당이다. 이번 작업은 **권오현이 뼈대(공통 구조·API 연결)와 대표 흐름을 먼저 잡는 것**이고(11/22 사용자 결정), 담당자가 그 위에서 이어 만들 수 있게 구조를 단순하게 둔다.

## 요청의 말
1. Next.js(App Router)로 `frontend/`에 웹 앱을 만든다. 언어는 TypeScript, 스타일은 Tailwind CSS(팀 미정 → 제안으로 적용, 바뀌면 따른다).
2. 화면은 390 CSS px를 모바일 기준으로 하고, 넓은 화면에서는 가운데 정렬한다(반응형 웹).
3. 브랜드 기본색 `#F74F85`와 `UI-DESIGN-SYSTEM.md`의 색·글꼴·둥근 모서리를 디자인 토큰으로 한곳에 모아 쓴다.
4. API는 `lib/api` 한곳에서만 부른다. 주소는 환경변수(`NEXT_PUBLIC_API_BASE`, 기본 `http://localhost:8000/api/v1`). 응답 타입은 모의 서버의 `openapi.json`에서 자동으로 만든다.
5. 오류는 공통 형식(`{"error": {code, message, request_id, retryable}}`)을 읽어 화면에 한국어 메시지로 보여 준다. 모의 응답이면(`is_mock`) 화면 구석에 "모의 데이터"를 표시한다.
6. 1차 화면: 홈 → 축제 목록·상세(현장 정보: 혼잡·날씨·통제 공지, 작은 지도) → **AI 안심 귀가**(출발·도착 → 접수 → 처리 중 → 결과, 지도에 경로선) → 로그인·회원가입. 찜·하트·관심 목록은 구현하지 않는다. 홈의 AI 질문창은 챗봇 작업(A06)으로 보내고, 귀가 질문이면 귀가 결과 화면으로 이어진다.
7. 지도는 카카오 지도 JavaScript SDK. 키는 `frontend/.env.local`(저장소에 올리지 않음)의 `NEXT_PUBLIC_KAKAO_JS_KEY`. 키가 없으면 지도 자리에 "지도 키가 없어요" 안내를 보여 주고 나머지 화면은 그대로 동작한다.
8. 아직 API가 없는 것(온보딩 취향·추천·동행·채팅·주변 시설·마이페이지)은 화면을 만들지 않거나 "준비 중"으로만 둔다. **가짜 데이터를 화면 코드에 직접 넣지 않는다**(데이터는 모두 모의 API에서).
9. 개인정보·키: 비밀번호·토큰을 로그·화면에 찍지 않는다. 카카오 키 외 다른 키를 쓰지 않는다.
10. 명령 한 줄로 실행·시험·빌드가 되어야 한다.
11. `backend/`, `infra/`, `Docs/`는 건드리지 않는다.
