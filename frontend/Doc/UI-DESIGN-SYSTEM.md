## 0. 디자인 의도 및 확정 사항

**기본 방향:** 흰 배경 + 로즈 핑크 포인트 + 차콜 텍스트. 정돈된 정보 위계, 충분한 여백, 세로로 자연스럽게 스크롤되는 모바일 웹. 기존 UI에 있던 물결무늬 배경, 불필요한 장식·진한 그라데이션을 재추가하지 않는다.

## 2. 타이포그래피

- 권장: `Pretendard`(프로젝트에 사용 권한·폰트 파일 로딩 방식 확인), 시스템 한글 대체 폰트 함께 설정.
- 로고는 **폰트로 재조합하지 않고 원본 이미지/SVG 사용**.
- 제목의 자간을 과하게 조이지 않는다. 한글은 기본 자간 `0`부터 검토하고 필요한 경우 `0.1px~0.2px` 미세 조정.

| 스타일 | 모바일 기본(제안) | 행간 | 예시 |
|---|---|---|---|
| Hero | 28~30px / 700~800 | 1.28 | 오늘, 여기서 놀다가! |
| Page title | 25~28px / 700 | 1.3 | 축제 / 마이페이지 |
| Section title | 20~22px / 700 | 1.35 | 인기있는 축제 |
| Card title(390px 3.5개) | 12~13px / 700 | 1.2 | 최대 2줄 |
| Body | 14~16px / 400~500 | 1.5 | 축제 소개·버튼 설명 |
| Caption | 11~12px / 400~600 | 1.35 | 날짜·지역 |
| CTA | 14~16px / 700 | 1.25 | 귀가 경로 확인하기 |

작은 포스터 내 제목/날짜는 폭이 매우 제한적이다. 읽기 어려우면 3.5개 노출을 무작정 유지하기보다 작은 뷰포트에 대한 예외 규칙을 디자인 검토한다.

## 3. 반응형 화면 규격

### 3.1 기기별 목표

| 화면 너비(CSS px) | 레이아웃 원칙 | 확인 사항 |
|---|---|---|
| 320~359 | 작은 모바일 | 이미지/텍스트 충돌 검사; 필요 시 **2.5장** 노출안 승인 후 적용 |
| 360~767 | 모바일 | **390 기준** 가로 스와이프·하단 탭 |
| 768~1023 | 태블릿 | 넓어진 카드 및 여백, 다열 화면 고려 |
| 1024 이상 | 데스크톱 | 최대 콘텐츠 폭 제한, 데스크톱 내비게이션 최종 확정 필요 |

- **390×844px으로 화면 전체를 고정하지 않는다.** 390은 디자인 너비이고 844는 한 기기 예시 높이일 뿐이다.
- 페이지의 세로 높이는 `height: auto`가 기본이며, 배너/섹션의 스크롤을 허용한다.
- `body`와 카드에 `transform: scaleX()` 등으로 화면 전체를 눌러 맞추지 않는다.
- 디자인 검토 PNG를 가로 1170px(3배)로 출력해도 **웹 레이아웃 단위는 CSS px**다.

## 4. 축제 포스터·썸네일 규격 — 최우선

### 4.1 정확한 비율

**포스터 콘텐츠 영역의 가로:세로 = 1:1.414.** 예를 들어:

| 카드 가로 | 이미지 세로(근삿값) |
|---|---|
| 95.4px | 134.9px |
| 100px | 141.4px |
| 120px | 169.7px |
| 160px | 226.2px |
| 200px | 282.8px |

**비율을 맞추기 위해 원본 이미지 자체를 압축·찌그러뜨리면 안 된다.** 이미지 표시 박스 크기와 원본 이미지 비율은 별개다.

- 실제 **축제 공식 포스터**: 원본 내용을 보호하려면 `object-fit: contain` + 여백 배경.
- 축제 **현장 사진**: 이미지 확대/중앙 크롭을 허용하면 `object-fit: cover`.
- 로고+`이미지 준비 중` 폴백 이미지는 동일한 1:1.414 프레임 안에서 중앙 정렬.
- 세로형 포스터와 가로형 현장 사진을 섞는 경우 자르기 정책을 명확히 구분.

### 4.2 모바일 390px / 3.5개 노출 계산

기준 가정: 화면 390px, 좌우 여백 각각 16px, 카드 사이 간격 8px.

- 화면 안 표시 폭 = `390 − 32 = 358px`
- 보이는 구간 = `카드 3.5개 + 간격 3개`
- 카드 폭 = `(358 − 8×3) / 3.5 = 약 95.43px`
- 포스터 높이 = `95.43 × 1.414 = 약 134.94px`

**이 값은 전체 카드 높이가 아닌 포스터 이미지 영역이다.** 이미지 위에 제목·날짜가 겹치는 기존 디자인이면 카드 전체도 포스터 높이와 동일하게 만들 수 있다.

> 3.5개는 카드를 4개 억지로 축소한 배치가 아니다. **첫 3개와 오른쪽에 잘린 네 번째**가 보여 사용자가 옆으로 밀도록 안내한다. 카드를 `overflow:hidden` 컨테이너로 자르되 다음 요소를 눌러 보이게 하면 안 된다.

### 4.3 구현 CSS(기본안)

```css
:root {
  --color-primary: #F74F85;
  --color-dark: #343536;
  --color-surface: #FFFFFF;
  --page-pad: 16px;
  --festival-gap: 8px;
  /* 390px에서 (390 - 32 - 24) / 3.5 = 약 95.43px */
  --festival-card-w: calc((100vw - 56px) * 0.285714);
}

.festival-carousel {
  display: flex;
  gap: var(--festival-gap);
  overflow-x: auto;
  scroll-snap-type: x proximity;
  overscroll-behavior-inline: contain;
  scrollbar-width: none;

}
.festival-carousel::-webkit-scrollbar { display: none; }

.festival-card {
  position: relative;
  flex: 0 0 var(--festival-card-w);
  scroll-snap-align: start;
  min-width: 0;
  border-radius: 12px;
  overflow: hidden;
}
.festival-card__media {
  width: 100%;
  aspect-ratio: 1 / 1.414;
  object-fit: cover; /* 공식 포스터면 contain 클래스로 변경 */

@media (max-width: 359px) {
```

**주의:** 화면 바깥의 고정 최대 너비 컨테이너(태블릿 데스크톱)를 쓰는 경우 `100vw` 대신 실제 캐러셀 `container width`를 기준으로 폭을 계산해야 한다. `ResizeObserver` 또는 CSS container query 방식은 팀 프레임워크/브라우저 지원 범위 확인 후 채택.

### 4.4 포스터 내용 배치

- 왼쪽 상단 D-day는 **실제 시작일까지 남은 날짜가 있을 때만**. 과거/진행 중/날짜 불명이면 문구 변경 또는 숨김.
- **오른쪽 상단 하트·찜 버튼은 없음.**
- 제목은 최대 **2줄**. 날짜/지역과 겹치지 않도록 아래쪽 오버레이 높이 확보.
- 날짜와 지역은 가능한 한 작은 아이콘과 짧은 표기, 말줄임은 마지막 수단.
- 하단 블랙 오버레이는 투명도 낮게. 이미지를 대부분 검게 덮지 않음.
- 과거 시안의 '인기 1위/맞춤추천/신규' 포스터 내부 배지는 제거. 다만 실제 데이터가 뒷받침되는 섹션 제목으로는 사용 가능.

## 5. 브랜드 로고/아이콘 규칙

- 기본 로고 **원본 비트맵 또는 검증된 SVG**로 배치. 새로 그리거나 O의 별 자리를 다시 조합하지 않음.
- 이미지 크기는 `width:auto`, `height:auto`, `object-fit:contain`을 사용해 원본 종횡비 유지.
- 헤더는 NOLDAGA 로고(좌), 프로필 버튼(우). **알림 종 없음**.
- 하단 5개 아이콘 순서·스타일 통일: `home`, `calendar-check`, `users-round`, `route`, `map-pin`에 준하는 윤곽 아이콘. 실제 확정 캡처와 다르면 캡처 우선.
- **마이페이지는 하단 탭이 아니다.** 상단 프로필 아이콘으로 열며 하단 5개 메뉴는 같은 순서를 유지하되 추가 선택 탭을 만들지 않음.
- 아이콘은 작은 모바일에서도 최소 24px 수준의 충분한 시각 크기; 클릭 영역은 **44×44px 이상**.

## 6. 공통 컴포넌트 디자인 규칙

### 6.1 `AIQuestionBar`
- 홈·축제·상세에서 **길게 가로로 이어지는 연한 핑크 테두리** 입력창 사용.
- 왼쪽 별 장식 + 가운데 질문 예시/입력 + 오른쪽 로즈 핑크 원형 제출 버튼.
- 바로 아래 예시 질문 칩 2개를 가로 배치. 예: '이번 주 서울 축제 알려줘', '친구와 함께 가기 좋은 축제는?'
- 축제 상세에서는 현재 축제 맥락으로 '이 축제 혼잡도 알려줘', '귀가하기 편한 길 알려줘' 등으로 변경 가능.
- 질문/응답이 **모의**인 경우 시연 환경에서 예시 응답임을 명시; 실제 안전 정보를 확인했다고 주장하지 않음.

### 6.2 `SafeReturnBanner`
- **차콜(`#343536`) 바탕**, 왼쪽 방패 아이콘, 우측 도로·지도 핀·교통 아이콘 조합, 핑크 CTA.
- 문구: 'AI 안심 귀가' / '축제 종료 후, 혼잡도와 동선을 고려한 가장 안전한 귀갓길을 안내해요!'는 기존 디자인 *홍보 문구*로 사용 가능하나 실제 경로 카드에서는 **안전을 보장하는 문구 금지**.
- 홈과 상세에서 **동일한 컴포넌트**를 재사용, 크기는 콘텐츠 너비에 따라 비율 유지.
- 외부 URL로 가지 않고 내부 '귀가' 페이지로 연결.

### 6.3 `FestivalSection`
- 구성: 왼쪽 세로 핑크 바 + 제목, 오른쪽 `전체보기/더보기` 차콜 텍스트 + 화살표.
- 축제 페이지 4개 섹션: 인기있는 축제 / 나만을 위한 축제 / 새로 올라온 축제 / 전체 축제.
- 각 섹션 카드 **같은 크기·같은 비율·같은 2줄 제목**; 섹션마다 독립 스와이프.
- AI 카드의 공식 포스터 이미지를 임의로 다른 사진으로 바꾸지 않음.

### 6.4 `FestivalDetail`
- 포스터 이미지 영역 1:1.414, 상단 AI 질문창+예시 칩, 상세 정보·주요 프로그램·주변 정보·동행 모집.
- **상단 저장/북마크 버튼 없음**(찜 미구현).
- '주변 지역 혼잡'은 단일 퍼센트가 아닌 4단계와 관측 시각/주변 3개 구역을 표시.
- 축제 데이터에 '주요 프로그램'·해시태그가 없으면 **섹션 자체를 숨김**.
- 지도에서 보기/AI 안심귀가 배너는 공통 컴포넌트.

### 6.5 `MyPage`
- 프로필 사진 변경 없음: 일반 사용자 아이콘 사용.
- 선택된 취향만 표시; 취향 변경 버튼은 따로 둔다.
- 내 동행 / 동행 채팅방 / 내 동행 활동 포함.
- 계정 및 설정: **계정 정보 및 비밀번호 변경 / 로그아웃** 두 항목만.
- 찜한 축제·맞춤 추천 바로가기(마이페이지 내 중복 카드)·알림 설정 없음.
