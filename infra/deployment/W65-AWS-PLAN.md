# W65 AWS 배포 구성도·체크리스트 초안

- 작성: 2026-11-26, R06 사전 준비
- 기준: `infra/deployment/compose.yaml`, `backend/Doc/w64/VERIFY-2026-11-25.md`
- 범위: 첫 AWS 배포의 단일 호스트 구성안. **AWS 기동·HTTPS·Redis·백업 복원은 아직 검증하지 않았다.** W65의 완료 판정은 실제 실행 기록으로 한다.

## 1. 첫 배포 구성안

```text
사용자 브라우저
    │ HTTPS 443
    ▼
EC2 보안 그룹 → HTTPS 역방향 프록시(호스트 또는 컨테이너)
                    │ 호스트 내부 연결
                    ▼
                 FastAPI :8000 ───── PostgreSQL 17 + pgvector :5432
                    │                 └ 영속 DB 볼륨
                    └────────────── Redis :6379 (연결 코드 준비 후)

EC2 내부 배치: migrate → role-passwords → API
추후 별도 실행: scheduler, A06 assistant_worker (해당 기능을 켤 때)
DB 논리 백업 → 비공개 S3 버킷 → 별도 시험 DB에 복원 확인
```

첫 배포는 **EC2 한 대의 Docker Compose**를 기준안으로 둔다. 현재 이미 검증한 이미지·마이그레이션 순서를 활용하기 위한 선택이며, 고가용성 구성은 아니다. EC2 또는 호스트 디스크 장애 시 서비스가 중단된다. 서버 크기·리전·도메인·예산은 배포 전에 확정한다.

| 항목 | 구성안 | 확인할 것 |
| --- | --- | --- |
| 외부 접속 | 보안 그룹 인바운드 443만 사용자에게 허용. 인증서 발급·갱신 방식에 따라 80을 일시 또는 상시 허용할지 결정 | 실제 도메인에서 HTTPS와 인증서 갱신 확인 |
| 운영자 접속 | AWS Systems Manager Session Manager 우선. SSH를 쓰면 관리자 주소로만 제한 | 접속 권한·감사 기록 확인 |
| API | 프록시에서만 접근. 현재 Compose의 `127.0.0.1:${API_PORT}:8000` 유지 가능 | 프록시를 거친 `/api/v1/health`와 외부 접속 확인 |
| DB | Compose 내부 `db:5432`만 사용. AWS에서는 DB의 호스트 `ports` 매핑 제거 | 인터넷·호스트 외부에서 5432 접근 불가, API 내부 연결 확인 |
| Redis | Compose 내부 `redis:6379`만 사용, 호스트 포트 공개 없음 | 실제 백엔드 연결 코드·환경변수·헬스체크 계약 확정 뒤 확인 |
| 데이터 | PostgreSQL 영속 볼륨을 EC2 영속 디스크에 배치. 컨테이너 재생성과 EC2 재시작 뒤 데이터 유지 | 볼륨 경로·용량·암호화·재기동 결과 확인 |
| 이미지 | 배포 시 Git 커밋과 이미지 태그·다이제스트 기록. 같은 버전으로 재기동 가능하게 보관 | 실제 실행 이미지의 버전·다이제스트 기록 |
| 비용 | EC2·EBS·S3·전송량·도메인·비밀값 보관·로그 비용을 배포 전 견적에 포함 | 예상 월 비용과 과금 알림 설정 |

프록시 제품과 인증서 발급 방식은 도메인·프론트 배포 위치를 확인한 뒤 고른다. 프론트가 같은 호스트에 놓이면 정적 파일 또는 별도 서비스로 프록시에서 분기하고, 별도 호스팅이면 API 도메인·CORS를 그 주소에 맞춘다. 이 문서는 프론트 배포 방식을 확정하지 않는다.

## 2. 현재 Compose에서 바꿀 부분

| 현재 W64 Compose | W65 적용 전 변경·확인 |
| --- | --- |
| `db`·`api` 포트를 각각 `127.0.0.1`에 게시 | DB 게시 제거. API는 프록시만 접근하도록 로컬 바인딩 또는 내부 네트워크로 제한 |
| `db → migrate → role-passwords → api` | 순서를 유지하고, 실패 시 API가 시작되지 않는지 AWS에서 확인 |
| `noldaga-db` 명명 볼륨 | 실제 EBS 저장 위치·용량·암호화·스냅샷 범위 확인 |
| Redis 서비스 없음 | `backend/shared/redis.py`는 아직 연결 구현 전이고 `/health`는 `not_configured`를 반환한다. 코드·환경변수 계약이 정해지면 서비스·헬스체크를 함께 추가 |
| API에 앱·서비스 DB 비밀번호 전달 | A05의 서비스 계정 필요 범위를 확인하고 서비스별 최소 비밀값만 전달. 관리자 DB 비밀번호는 API에 전달하지 않음 |
| `scheduler`는 선택 프로필 | 실제 공급원 키·수집 정책 확인 뒤 켜고 실행 결과를 기록 |
| A06 워커 서비스 없음 | `ASSISTANT_PROVIDER=db`를 켤 때 별도 워커 실행·재시작·DB 연결을 구성. 워커 업무 입력은 DB의 `run_id`로 식별 |

비밀값은 이미지·Git에 넣지 않는다. **기준안은 AWS Systems Manager Parameter Store 또는 Secrets Manager에서 배포 시 읽어 서버의 권한 제한 파일에 주입**하는 것이다. 어떤 서비스를 쓸지 비용·권한을 비교해 배포 전 확정한다. 임시 파일은 운영자와 실행 서비스만 읽게 하고, 로그·`docker inspect`·이미지 히스토리 노출 여부를 재검사한다. 환경변수 주입 자체는 `docker inspect` 접근 권한을 가진 운영자에게 보이므로 Docker 제어 권한도 제한한다.

## 3. 백업·복원 설계

현재 `Docs/Step 2/db/backup_long_term.sh`는 `pg_dump --format=custom`을 사용하고 `public.route_results`의 **행 데이터**를 제외한다. 백업에는 그 밖의 사용자·축제·운영 데이터가 들어갈 수 있으므로 비공개 S3 버킷에 암호화해 저장하고 접근 역할을 제한한다. 7일 보존은 기존 배포 문서의 계획으로 두되, 실제 실행 주기·시각·보존 정책은 W65에서 고정한다. DB 볼륨 스냅샷만으로 논리 백업을 대체하지 않는다.

복원은 운영 DB를 덮어쓰지 않는 **별도 시험 DB**에서 먼저 수행한다. 스키마·축제 조회·사용자 권한 문맥·삭제/만료 정책을 검증하고, 백업 시점 이후의 탈퇴·삭제 요청을 복원본에 다시 반영하는 절차를 확정한다. 그 절차가 마련되기 전에는 복원 성공을 운영 복구 완료로 판정하지 않는다. RPO·RTO 목표값은 팀이 정하고, W67에서 실제 복원 시간을 측정한다.

## 4. 배포 체크리스트와 완료 증거

| 단계 | 할 일 | 남길 증거 |
| --- | --- | --- |
| 배포 전 | 리전·EC2 크기·도메인·프록시/인증서 방식·프론트 위치·비용 상한 확정 | 구성도 버전과 결정 기록 |
| 접근 통제 | 보안 그룹 443(필요 시 80)·운영자 접속만 허용, DB/Redis 포트 외부 비공개 | 보안 그룹 규칙과 외부 포트 확인 결과 |
| 저장·비밀값 | EBS·DB 볼륨·백업 버킷·암호화·접근 역할·비밀값 주입 방식 설정 | 볼륨/버킷 설정과 비밀값 비노출 검사 결과 |
| 기동 | 고정 이미지로 DB→001~최신 마이그레이션→비밀번호 설정→API, 재실행 시 기존 마이그레이션 건너뛰기 | 서비스 상태·마이그레이션 실행/재실행 로그 |
| 데이터 | 별도 시험 DB에 축제 데이터를 적재해 A02·A03에서 같은 ID 조회 | `is_mock=false`, 0건보다 많은 목록과 상세 응답 |
| Redis | 백엔드 코드·환경변수 확정 뒤 연결 및 장애 응답 확인 | 실제 연결 결과와 `/health` 응답. 그 전에는 `not_configured` 유지 |
| 외부 접속 | 도메인의 HTTPS에서 API·필요한 웹 화면 접속, 인증서 갱신 확인 | 외부 URL·HTTP 상태·인증서·접속 시각 |
| 백업·복원 | 논리 백업을 비공개 저장소에 올리고 별도 DB에 복원, 권한·삭제/만료 재적용 확인 | 백업 시각·객체·복원 시험·소요 시간 |
| 운영 판정 | 이미지 다이제스트·비용·로그·접근권한·남은 제한을 기록 | W65 검증 기록. W64 로컬 결과와 구분 |

## 5. 현재 판정

W64의 로컬 Docker 기동·001~028 적용·재실행·DB 헬스·비밀값 검사는 통과했다. 이 문서는 **W65 준비용 구성안**이며 AWS 자원 생성, Redis 연결, HTTPS, 실제 데이터 조회, 백업·복원 완료를 주장하지 않는다.
