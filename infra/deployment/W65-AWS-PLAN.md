# W65 AWS 첫 배포 구성안·체크리스트

- 작성: 2026-11-26, R06 사전 준비
- 기준: `infra/deployment/compose.yaml`, `backend/Doc/w64/VERIFY-2026-11-25.md`
- 범위: 첫 AWS 배포의 단일 호스트 구성안. **AWS 기동·HTTPS·백업 복원은 아직 검증하지 않았다.** W65의 완료 판정은 실제 실행 기록으로 한다. 로컬 Redis·A06 워커·시험 DB 축제 조회는 별도 검증 기록에 있다.
- 실행 절차: [W65-AWS-RUNBOOK.md](W65-AWS-RUNBOOK.md). AWS 전용 포트·HTTPS 설정은 `compose.aws.yaml`과 `Caddyfile`에 둔다.

## 1. 첫 배포 구성안

```text
사용자 브라우저
    │ HTTPS 443
    ▼
EC2 보안 그룹 → Caddy HTTPS 프록시 컨테이너
                    │ 호스트 내부 연결
                    ▼
                 FastAPI :8000 ───── PostgreSQL 17 + pgvector :5432
                    │                 └ 영속 DB 볼륨
                    └────────────── Redis :6379 (선택 프로필)

EC2 내부 배치: migrate → role-passwords → API
추후 별도 실행: scheduler, A06 assistant_worker (해당 기능을 켤 때)
DB 논리 백업 → 비공개 S3 버킷 → 별도 시험 DB에 복원 확인
```

첫 배포는 **EC2 한 대의 Docker Compose**를 기준안으로 둔다. 현재 이미 검증한 이미지·마이그레이션 순서를 활용하기 위한 선택이며, 고가용성 구성은 아니다. EC2 또는 호스트 디스크 장애 시 서비스가 중단된다. 서버 크기·리전·도메인·예산은 배포 전에 확정한다.

| 항목 | 구성안 | 확인할 것 |
| --- | --- | --- |
| 외부 접속 | 첫 배포는 Caddy 자동 HTTPS로 결정. 보안 그룹 인바운드 80·443을 허용하고 80은 인증서 발급/갱신과 HTTPS 리다이렉트에 사용 | 실제 DNS에서 HTTPS·리다이렉트·인증서 갱신 확인 |
| 운영자 접속 | AWS Systems Manager Session Manager 우선. SSH를 쓰면 관리자 주소로만 제한 | 접속 권한·감사 기록 확인 |
| API | 프록시에서만 접근. 현재 Compose의 `127.0.0.1:${API_PORT}:8000` 유지 가능 | 프록시를 거친 `/api/v1/health`와 외부 접속 확인 |
| DB | Compose 내부 `db:5432`만 사용. AWS 오버레이에서 DB의 호스트 `ports` 제거 | 인터넷·호스트 외부에서 5432 접근 불가, API 내부 연결 확인 |
| Redis | 선택 프로필의 `redis:6379`만 사용, 호스트 포트 공개 없음 | AWS에서 실제 `/health redis=ok`와 중단 시 503 확인 |
| 데이터 | PostgreSQL 영속 볼륨을 EC2 영속 디스크에 배치. 컨테이너 재생성과 EC2 재시작 뒤 데이터 유지 | 볼륨 경로·용량·암호화·재기동 결과 확인 |
| 이미지 | 배포 시 Git 커밋과 이미지 태그·다이제스트 기록. 같은 버전으로 재기동 가능하게 보관 | 실제 실행 이미지의 버전·다이제스트 기록 |
| 비용 | EC2·EBS·S3·전송량·도메인·비밀값 보관·로그 비용을 배포 전 견적에 포함 | 예상 월 비용과 과금 알림 설정 |

프론트가 같은 호스트에 놓이면 별도 정적 파일 또는 서비스 구성을 추가하고, 별도 호스팅이면 API 도메인·CORS를 그 주소에 맞춘다. **API 도메인, 프론트 위치, AWS 리전·계정·서버 사양·예산은 배포 전 실제 팀 정보를 받아 채워야 한다.** 현재 문서의 구성 결정은 이 값을 가정해 AWS 자원을 생성했다는 뜻이 아니다.

## 2. 현재 Compose에서 바꿀 부분

| 현재 W64 Compose | W65 적용 전 변경·확인 |
| --- | --- |
| `db`·`api` 포트를 각각 `127.0.0.1`에 게시 | `compose.aws.yaml`의 `!reset []`로 둘 다 호스트 포트 게시 제거. Caddy만 80·443 게시 |
| `db → migrate → role-passwords → api` | 순서를 유지하고, 실패 시 API가 시작되지 않는지 AWS에서 확인 |
| `noldaga-db` 명명 볼륨 | 실제 EBS 저장 위치·용량·암호화 확인. 경로 결과 보존 규칙상 DB 볼륨 스냅샷을 백업으로 사용하지 않음 |
| Redis 선택 프로필 | 로컬 연결·중단·복구 검증 완료. AWS에서는 `REDIS_URL`과 `--profile redis`를 함께 사용하고 실제 연결 재검증 |
| API에 앱·서비스 DB 비밀번호 전달 | A05의 서비스 계정 필요 범위를 확인하고 서비스별 최소 비밀값만 전달. 관리자 DB 비밀번호는 API에 전달하지 않음 |
| `scheduler`는 선택 프로필 | 실제 공급원 키·수집 정책 확인 뒤 켜고 실행 결과를 기록 |
| A06 워커 선택 프로필 | 로컬 접수→완료/실패 조회 검증 완료. AWS에서 `ASSISTANT_PROVIDER=db`를 켜면 `--profile assistant`도 함께 사용하고 재시작·실제 Agent 연동을 별도로 검증 |

비밀값은 이미지·Git에 넣지 않는다. 첫 배포 기준안은 **AWS Secrets Manager에 DB 비밀번호·API 키·토큰 서명 키를 보관**하고, 인스턴스 역할이 필요한 항목만 읽어 권한 제한된 런타임 파일로 전달하는 것이다. 자동 교체는 이번 범위에 넣지 않는다. 실제 저장 경로·IAM 정책·비용은 계정 정보로 확인한다. 환경 파일과 `docker inspect`를 읽을 수 있는 운영자 권한을 제한하고, 로그·이미지 히스토리 노출을 재검사한다.

## 3. 백업·복원 설계

현재 `Docs/Step 2/db/backup_long_term.sh`는 `pg_dump --format=custom`을 사용하고 `public.route_results`의 **행 데이터**를 제외한다. 첫 배포 기준안은 **매일 KST 06:30에 논리 백업을 생성해 비공개·암호화 S3 버킷에 저장하고 7일 만료 규칙을 적용**하는 것이다. 06:00 정기 작업과 겹치면 순서를 조정한다. 백업에는 그 밖의 사용자·축제·운영 데이터가 들어갈 수 있으므로 접근 역할을 제한한다. S3 수명주기 삭제는 비동기이므로 실제 7일 삭제를 요구하는 정책이라면 만료 객체 확인·추가 삭제 절차가 필요하다. DB 볼륨 스냅샷은 경로 결과 보존 규칙 때문에 백업 수단으로 사용하지 않는다.

복원은 운영 DB를 덮어쓰지 않는 **별도 시험 DB**에서 먼저 수행한다. 스키마·축제 조회·사용자 권한 문맥·삭제/만료 정책을 검증하고, 백업 시점 이후의 탈퇴·삭제 요청을 복원본에 다시 반영하는 절차를 확정한다. 그 절차가 마련되기 전에는 복원 성공을 운영 복구 완료로 판정하지 않는다. RPO·RTO 목표값은 팀이 정하고, W67에서 실제 복원 시간을 측정한다.

## 4. 배포 체크리스트와 완료 증거

| 단계 | 할 일 | 남길 증거 |
| --- | --- | --- |
| 배포 전 | 리전·EC2 크기·도메인·프록시/인증서 방식·프론트 위치·비용 상한 확정 | 구성도 버전과 결정 기록 |
| 접근 통제 | 보안 그룹 80·443과 운영자 Session Manager만 허용, DB/Redis 포트 외부 비공개 | 보안 그룹 규칙과 외부 포트 확인 결과 |
| 저장·비밀값 | EBS·DB 볼륨·백업 버킷·암호화·접근 역할·비밀값 주입 방식 설정 | 볼륨/버킷 설정과 비밀값 비노출 검사 결과 |
| 기동 | 고정 이미지로 DB→001~최신 마이그레이션→비밀번호 설정→API, 재실행 시 기존 마이그레이션 건너뛰기 | 서비스 상태·마이그레이션 실행/재실행 로그 |
| 데이터 | 별도 시험 DB에 축제 데이터를 적재해 A02·A03에서 같은 ID 조회 | `is_mock=false`, 0건보다 많은 목록과 상세 응답 |
| Redis | `REDIS_URL`과 선택 프로필로 실제 연결·장애 응답 확인 | AWS `/health redis=ok`, 중단 시 `unavailable`·503 |
| 외부 접속 | 도메인의 HTTPS에서 API·필요한 웹 화면 접속, 인증서 갱신 확인 | 외부 URL·HTTP 상태·인증서·접속 시각 |
| 백업·복원 | 논리 백업을 비공개 저장소에 올리고 별도 DB에 복원, 권한·삭제/만료 재적용 확인 | 백업 시각·객체·복원 시험·소요 시간 |
| 운영 판정 | 이미지 다이제스트·비용·로그·접근권한·남은 제한을 기록 | W65 검증 기록. W64 로컬 결과와 구분 |

## 5. 현재 판정

W64 로컬 기동과 A06 워커·Redis·시험 DB 축제 목록/상세의 로컬 검증은 통과했다. 이 문서는 **W65 AWS 적용 전 구성안**이며 AWS 자원 생성, HTTPS, 실제 TourAPI 데이터 조회, 백업·복원 완료를 주장하지 않는다.
